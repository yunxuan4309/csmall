## 🔴 #F1 AI 回复的 Markdown 表格不渲染（🆕 2026-09-10，用户实测反馈）

**现象**：AI 助手回答里的对比表格在页面上显示为原始竖线（`|机型|价格|说明|`），"表格没加载出来"。

**证据（源码级）**：

| 证据 | 位置 |
|---|---|
| `formatMarkdown()` 只处理 **加粗 / `#` 标题 / 列表 / 换行**，**无表格解析** | `src/views/front/ai/AIAssistant.vue` L389-410 |
| `FloatingAI.vue` 的同名函数**连标题和列表都没有**（只有加粗+换行）—— 两处实现已漂移 | `src/components/common/FloatingAI.vue` L409-422 |
| `package.json` 无任何 markdown 渲染库（`marked`/`markdown-it`/`DOMPurify` 均无） | `package.json` |
| 渲染方式为 `v-html="formatMarkdown(msg.text)"`（已转义 `<`/`>`，安全） | 两个组件模板 |

> ⚠️ **不是 Agent 引入的**：旧 RAG 回答也带表格；只是 Agent 更爱用表格，所以现在更明显。

**方案**：见 [[补丁-AI回复Markdown表格渲染]]（**推荐**）—— 抽公共 `src/utils/formatMarkdown.js`，支持 GFM 管道表格 + 补齐悬浮窗的标题/列表，并加表格 CSS（窄屏横向可滑）。
**备选**：后端 `ChatServiceImpl.buildAgentSystemPrompt()` 增加"不要用 Markdown 表格，改用 `### 标题 + 有序列表 + 加粗`" —— 前端零改动，但要一次 mall-ai 部署（页面版已支持这些格式，悬浮窗仅支持加粗）。

**工作量**：前端 1~2h（含 build 与验证）；备选后端 0.5h + 1 次部署。
**验收**：AI 助手里问"3000 元左右适合学生用的手机"，表格渲染成**带边框真表格**；窄屏（≤390px）可横向滑动不撑破气泡；悬浮窗里标题/列表/表格同样正常。

## 🟠 #F2 iPhone 底部安全区未适配（H5）

**现象**：iPhone 底部 Home 指示条会盖住贴底元素。

**证据**：全仓库 `env(safe-area-inset*)` **0 处**；而 `FloatingAI.vue` 移动端是 `position:fixed; bottom:0; height:80vh`（L~）—— 典型受害页；另有 2 处 `position:fixed` 也未做安全区。

**方案**：统一加 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`（悬浮面板、悬浮按钮、底部操作栏）；`viewport` meta 可加 `viewport-fit=cover`（**注意**：加了才需要安全区适配，二者配套）。
**工作量**：0.5h（纯 CSS）。
**验收**：iPhone 12/13/14/15（或有底部横条的模拟器）下，悬浮 AI 面板底部按钮/输入框不被遮挡。

## 🟠 #F3 悬浮面板使用 `100vw`（易横向溢出）

**证据**：`FloatingAI.vue` 移动端 `.floating-panel { width: 100vw !important; }`（1 处 `100vw`）。
**问题**：iOS 上 `100vw` **包含滚动条宽度** → 页面出现约 1~15px 横向滚动/抖动。
**方案**：改 `width: 100%`（父级已是视口宽）；顺带 `max-width: 100vw` 兜底。
**工作量**：10 分钟。**验收**：iOS Safari 打开悬浮面板无横向滚动条。

## 🟠 #F4 移动端点击反馈缺失（`-webkit-tap-highlight-color`）

**证据**：全仓库 `-webkit-tap-highlight-color` **0 处**、`touch-action` **0 处**。
**问题**：Android/iOS 点击卡片、按钮时出现系统灰块，且部分场景双击缩放影响连贯操作。
**方案**：全局样式补 `-webkit-tap-highlight-color: transparent;` + 关键可点区域 `touch-action: manipulation;`（消除 300ms 双击缩放等待）。
**工作量**：0.5h。**验收**：真机上点击商品卡/按钮无灰块、连点不误触缩放。

## 🟠 #F5 图片无懒加载、无骨架屏（移动端性能）

**证据**：`loading="lazy"` **0 处**；`el-skeleton` **0 处**；`:src` 绑定 **23 处**。商品列表/详情/秒杀都是图片密集页。
**影响**：移动网络下首屏慢、流量大；图片未就绪时布局跳动（CLS）。
**方案**：① 列表/详情图片加 `loading="lazy"` + `decoding="async"`；② 首屏关键图加 `fetchpriority="high"`；③ 列表加轻量骨架（可用 `el-skeleton` 或纯 CSS 占位）；④ 图片容器固定宽高比（防跳动）。
**工作量**：1~2h。**验收**：Lighthouse（移动模拟 4G）性能分提升；首屏可交互时间下降；滚动时图片按需加载。

## 🟠 #F6 未配 PostCSS/autoprefixer（工程化）

**证据**：`package.json` 无 `postcss`/`autoprefixer`/`browserslist`；`vite.config.js` 仅 `@vitejs/plugin-vue`。
**影响**：老版本 iOS Safari / Android WebView 上缺少 `-webkit-` 前缀的属性可能失效（现代浏览器影响小，但属低成本加固）。
**方案**：加 `postcss.config.js`（`autoprefixer`）+ `package.json` 的 `browserslist`（如 `> 0.5%, last 2 versions, iOS >= 13, not dead`）。
**工作量**：0.5h。**验收**：构建产物含 `-webkit-backdrop-filter` 等前缀。
