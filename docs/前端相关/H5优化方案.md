# H5（移动端 Web）优化方案 —— 现状评估 + 计划

> **创建日期**: 2026-09-10
> **状态**: 📋 **评估完成 · 计划待执行**（P0 可立即开工；P1/P2 待排期）
> **定位**: 本文是**前端 H5/移动端**的评估与计划底稿；**待办状态源**在 [[前端TODO]]（条目 `#F1~#F12`）。
> **调研对象**: 前端仓库 `D:\Vue-Workspace\csmall-vue`（**实读源码 + 逐项统计**，非凭印象）
> **一句话结论**: **不是"零移动端"** —— 全站有 `@media (max-width:767px)` 断点覆盖（15/17 页）、
> 汉堡菜单+抽屉导航、商品网格自适应、悬浮窗移动端降级为底部面板；**缺口集中在"体验细节（安全区/点击反馈）、
> 性能（图片懒加载/骨架屏）、工程化（PostCSS/NutUI 死依赖）与验收流程"**，而不是"要从头做 H5"。

## 二、现状评估

### 2.1 已具备的移动端能力（好消息，先说清）

| 能力 | 证据 |
|---|---|
| **viewport 正确** | `index.html`: `<meta name="viewport" content="width=device-width, initial-scale=1.0">` ✓ |
| **成体系的断点** | `@media (max-width: 767px)` **32 处**（+ 平板 768~991 **4 处**、≥1920 **2 处**）→ 约定是"**桌面优先 + <768 降级**" |
| **页面级覆盖** | `views/front/**` **15/17 个页面**都有 767 断点（仅 `PayResult.vue`、`HelloWorld.vue` 缺）|
| **导航降级** | `FrontLayout.vue`：桌面 `el-menu.nav-menu.hide-xs-only` → 移动端 **`mobile-menu-btn` + `el-drawer`** ✓ |
| **后台降级** | `AdminLayout.vue`：侧边栏 `hide-xs-only` → 移动端抽屉（`el-drawer.show-xs-only`）✓ |
| **响应式网格** | 商品网格用 `repeat(auto-fill, minmax(140px, 1fr))` ✓（390px 手机自然 2 列，不会挤成 4 列）|
| **悬浮 AI 降级** | `FloatingAI.vue`：移动端 `.floating-panel{ bottom:0; width:100vw; height:80vh }` + 按钮 48px ✓（**方向对**，细节见 #F2/#F3）|
| **单套代码** | 路由无 `/m` 分支（`path: '/'`, `products`, `product/:id`, `seckill`, `ai`, `cart`, `order/*`…）→ **响应式单套**是正确取舍（维护成本最低）|
| **移动端工具类约定** | `hide-xs-only` **11 处** / `show-xs-only` **4 处** → 已有约定，**应沿用并文档化** |

### 2.3 缺口一览（本次新发现，均带证据）

| # | 缺口 | 证据（实测） | 影响 | 条目 |
|---|---|---|---|---|
| 1 | **AI 回复 Markdown 表格不渲染** | `formatMarkdown()` 无表格解析；`FloatingAI` 版连标题/列表都无 | 用户已反馈"表格没加载出来" | **#F1** |
| 2 | **iPhone 安全区未适配** | `env(safe-area-inset*)` **0 处**；悬浮面板贴底 `bottom:0` | 底部横条遮挡按钮/输入框 | **#F2** |
| 3 | **`100vw` 引发横向溢出** | `FloatingAI` 移动端 `width:100vw !important`（1 处）| iOS 上横向滚动/抖动 | **#F3** |
| 4 | **点击反馈缺失** | `-webkit-tap-highlight-color` **0 处**、`touch-action` **0 处** | 点击灰块、双击缩放误触 | **#F4** |
| 5 | **图片无懒加载/骨架** | `loading="lazy"` **0 处**、`el-skeleton` **0 处**、`:src` **23 处** | 移动网络首屏慢、布局跳动 | **#F5** |
| 6 | **无 PostCSS/autoprefixer** | `package.json` 无 postcss/browserslist；vite 仅 vue 插件 | 老 iOS/WebView 前缀风险 | **#F6** |
| 7 | **NutUI 死依赖** | 装了 `@nutui/nutui ^4.3.14`，`<nut-*>` 使用 **0 处** | 认知负担 / 依赖冗余 | **#F7** |
| 8 | 两个文件缺断点 | `PayResult.vue`、`HelloWorld.vue` | 支付结果页手机上排版风险 | **#F8/#F9** |
| 9 | 无移动端验收流程 | 本次才发现"表格不渲染"→ 说明缺走查 | 问题靠用户撞见 | **#F10** |
| 10 | admin 表格桌面专用 | `el-table` 91 处（admin 为主）| 后台手机上体验差 | **#F11** |
| 11 | 无触摸手势 | `touch`/`swipe` **0 处** | 轮播/拖拽在触屏不可用 | **#F12** |

### 2.4 移动端关键路径现状（买家主流程）

| 路径 | 现状 | 风险点 |
|---|---|---|
| 首页 → 商品列表 | ✅ 网格自适应（2 列）+ 筛选区在 767 下换行全宽 | 筛选控件较多时易长；无吸顶（可选优化）|
| 商品列表 → 商品详情 | ✅ 详情有断点；轮播为静态/无手势 | 无 swipe 轮播（#F12）；图片无懒加载（#F5）|
| 详情 → 加购 → 购物车 | ✅ `CartList` 有断点、无表格 | 数量控件触控目标是否 ≥44px 需走查（#F10）|
| 结算 → 下单 → 支付 | ✅ `OrderSettle/OrderPay` 有断点 | `PayResult` 无断点（#F8）|
| 秒杀页 | ✅ `SeckillDetail/List` 有断点、倒计时 | 倒计时/抢购按钮的触控与吸底栏需走查 |
| **AI 智能问答** | ⚠️ 可用但**表格不渲染** | **#F1（明天做）**；悬浮窗内格式更弱 |
| 登录/注册/个人中心 | ✅ 有断点 | 表单键盘弹起遮挡（建议走查） |

## 三、优化计划（三阶段）

### P0 · 立即可做（预计 **半天~1 天**，纯前端小改 + 低风险）

| 项 | 做什么 | 工作量 | 验收 |
|---|---|---|---|
| **#F1** | 抽公共 `src/utils/formatMarkdown.js`：**GFM 表格渲染** + 补齐悬浮窗标题/列表 + 表格 CSS（窄屏 `overflow-x:auto`）| 1~2h | AI 助手里表格变**带边框真表格**；390px 可横向滑动；悬浮窗同样正常 |
| **#F2** | 安全区：悬浮面板/悬浮按钮/贴底栏 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`；`viewport` 加 `viewport-fit=cover` | 0.5h | iPhone 底部横条不遮挡按钮/输入框 |
| **#F3** | `100vw` → `100%`（+`max-width:100vw` 兜底）| 10min | iOS Safari 无横向滚动 |
| **#F4** | 全局 `-webkit-tap-highlight-color: transparent`；可点区域 `touch-action: manipulation` | 0.5h | 真机点击无灰块、连点不缩放 |
| **#F8/#F9** | `PayResult.vue` 补 767 断点；删 `HelloWorld.vue` | 0.5h | 390px 下支付结果页无横向滚动；无残留引用 |

**部署**：`npm run build` → 覆盖 `/data/csmall/frontend/dist` → 容器内 `docker cp`（**不必重建镜像**，因服务器无 `nginx:alpine`；详见 [[补丁-AI回复Markdown表格渲染]] §四）。**回滚**：`dist` 备份目录换回即可（静态资源，秒级）。

### P1 · 体验与性能（预计 **1~1.5 天**）

| 项 | 做什么 | 工作量 |
|---|---|---|
| **#F5** | 图片 `loading="lazy"` + `decoding="async"`；首屏关键图 `fetchpriority="high"`；列表轻量骨架；图片容器固定宽高比（防跳动）| 1~2h |
| **#F6** | 加 `postcss.config.js`（autoprefixer）+ `browserslist`（`iOS >= 13` 等）| 0.5h |
| **#F7** | **NutUI 决策**：删除（默认）或启用（`Swipe/Picker/Sticky/PullRefresh`）| 10min / 视组件 |
| **#F10** | 落地《移动端验收清单 + 设备矩阵 + Lighthouse 基线》（见 §四）| 1h |

### P2 · 深化（可选，**2~3 天**，有明确诉求再做）

- 移动端交互：商品图 **Swipe 轮播**、列表**吸顶筛选**、**下拉刷新**、底部 **TabBar**（首页/分类/购物车/我的/AI）
- **#F12** 手势：统一用 NutUI 组件而非自研（避免引入 hammer.js）
- **#F11** admin 移动端边界：显式声明"桌面专用"，或做只读卡片化（成本高，建议仅声明）
- 性能预算与回归：CI 里跑 Lighthouse（移动 4G 模拟）设阈值（性能 ≥ 80 等）

## 四、验收标准（#F10 要落地的东西）

**设备/尺寸矩阵**

| 档位 | 代表 | 检查 |
|---|---|---|
| 窄手机 | iPhone SE / 375×667 | 无横向滚动、触控目标 ≥44px、文字不截断 |
| 主流手机 | iPhone 14 / 390×844、Android 中端 | 主流程可完成、贴底元素不被安全区遮挡 |
| 折叠/平板 | 768×1024 | 断点切换正确（767/768 边界）|
| 桌面 | 1440×900、1920×1080 | 无回归（桌面优先的设计不能被移动端改动破坏）|

**逐页检查项（每页 6 条）**：① 无横向滚动 ② 触控目标 ≥44px ③ 文字可读（≥12px 且行高足够）④ 图片不撑破容器、不跳动 ⑤ 关键操作可完成（加购/下单/AI 提问）⑥ 无遮挡（安全区、键盘弹起）。

**性能基线（Lighthouse 移动 4G 模拟）**：记录首屏 LCP / TBT / CLS 三项**当前值**作为基线，P1 后对比；
验收：LCP 与 CLS 不劣化、图片懒加载生效（Network 面板按需加载）。

## 五、风险与回滚

| 风险 | 说明 | 缓解 |
|---|---|---|
| 改动影响桌面端 | 移动端补丁多用媒体查询/全局样式 | 每项都在 1440/1920 宽度回归（§四矩阵）|
| `viewport-fit=cover` 副作用 | 加了之后必须配套安全区，否则内容可能贴到刘海 | **#F2 的 CSS 与 meta 同一提交**一起上 |
| 前端无自动化测试 | 目前靠手工走查 | **#F10** 清单化；关键页可后续加 Playwright 冒烟（另立项）|
| 部署路径 | 服务器**无 `nginx:alpine` 基础镜像**，`docker compose build frontend` 会尝试拉取 | 用 `docker cp` 快速生效 + 同时覆盖 `/data/csmall/frontend/dist`（源文件），重建窗口再正规构建 |
| NutUI 启用后视觉不统一 | 与 Element Plus 混用 | 若启用，先做 1 个组件试点（如 Swipe），统一间距/主色变量 |
