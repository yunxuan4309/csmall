# 前端体验优化与后端缺陷修复 — 问题排查与解决方案

> 日期：2026-07-31
> 涉及模块：csmall-vue 前端、mall-order、mall-front、mall-product、mall-seckill、nginx

---

## 一、前端图片加载失败

**现象**：商品列表、秒杀列表、商品详情中的图片显示为占位图。

**根因**：后端返回的 `pictures` 字段是裸文件名（如 `["spu_1_1.jpg"]`），浏览器按相对路径解析。服务器上可工作（nginx 静态文件），本地 Vite 代理不转发图片请求。

**修复**：4 个页面的图片处理函数统一补全 `window.location.origin` 前缀。
- `SeckillList.vue` / `ProductList.vue` — `getFirstImage()` 加前缀
- `ProductDetail.vue` / `SeckillDetail.vue` — `imageList` computed 加前缀

## 二、秒杀页面刷新 401 + 秒杀下单 405

**现象**：
1. 访问 `/seckill/1` 刷新页面返回 `{"state":401,"您没有登录！"}`
2. 秒杀下单 `POST /seckill/{randCode}` 返回 405 Method Not Allowed

**根因**：nginx 的 API 正则 `^/(...seckill...)/` 匹配了所有 `/seckill/**` 路径，单段 SPA 路由（如 `/seckill/1`、`/seckill/{randCode}`）被误当 API 转发。加 SPA 保护后，`try_files` 对 POST 请求返回 405。

**修复**：`nginx.conf` 新增 SPA 短路径保护规则，GET 走 SPA，非 GET 直通 Gateway：
```nginx
location ~ ^/seckill/?\d*$ {
    if ($request_method = GET) {
        rewrite ^ /index.html last;
    }
    proxy_pass http://mall-gateway:10087;
    ...
}
```

## 三、搜索功能卡死与超时

**现象**：从搜索栏搜索后点击商品，页面持续 loading 超过 15 秒报 `timeout`。

**根因**：
1. `ProductList.vue` 中 `watch(immediate:true)` 和 `onMounted` 各触发一次 `fetchProductList()`，双重并发调用 AI 搜索 API
2. AI 搜索默认超时 15s 不够（DeepSeek 排序耗时 5~15s）

**修复**：
- `ProductList.vue` — `onMounted` 去重，搜索模式只由 `watch(immediate)` 触发
- `api/search.js` — 搜索/补全/推荐超时统一 30s

## 四、搜索用户体验优化

**现象**：
1. 搜索栏没有点击搜索的按钮，只能回车
2. 搜索后无法回到商品列表页
3. 离开搜索页再回来，重新加载很慢

**修复**：
- `FrontLayout.vue` — 搜索框右侧加圆形搜索按钮
- `ProductList.vue` — 搜索模式下显示「← 返回商品列表」按钮 + 搜索结果前端缓存
- `FrontLayout.vue` — `<keep-alive>` 缓存 ProductList/SeckillList 组件，离开再回来秒开

## 五、手机号正则不支持 16/17 号段

**现象**：部分合法手机号（166、173 等）注册时提示格式不正确。

**根因**：`constants.js` 中 `REGEX_PHONE = /^1[34589]\d{9}$/` 缺少 6、7。

**修复**：改为 `/^1[3-9]\d{9}$/`，覆盖 13~19 全号段。

## 六、删除订单 404

**现象**：订单列表页删除订单报 `No static resource oms/order/delete/xxx`。

**根因**：后端 `OmsOrderController` 没有 `DELETE /oms/order/delete/{id}` 端点。

**修复**：新增完整的删除端点链路：
- `IOmsOrderService` — 新增 `deleteOrder(Long orderId)` 接口
- `OmsOrderServiceImpl` — 实现：权限校验 + MyBatis-Plus `deleteById`
- `OmsOrderController` — `@DeleteMapping("/delete/{id}")`

---

## 七、全部商品 API

**现象**：「查看全部」按钮清空筛选后显示空列表，无 API 支持"不限分类查询"。

**根因**：`GET /front/spu/list/{categoryId}` 必须传分类 ID，没有"全部商品"端点。

**修复**：7 个文件新增 `GET /front/spu/list/all` 端点：
| 层 | 文件 | 改动 |
|------|------|------|
| Dubbo 接口 | `IForFrontSpuService.java` | + `listSpuByPage(page, pageSize)` |
| Dubbo 实现 | `ForFrontSpuServiceImpl.java` | 去掉 `categoryId` 过滤，提取 `toSpuListItemPage` 复用 |
| Front 接口 | `IFrontProductService.java` | + `listSpuByPage` |
| Front 实现 | `FrontProductServiceImpl.java` | Dubbo 透传 |
| Controller | `FrontSpuController.java` | `@GetMapping("/list/all")` |
| 前端 API | `spu.js` | + `getFrontAllSpuList` |
| 前端页面 | `ProductList.vue` | 无分类时调用全部商品 API |

## 八、立即购买逻辑修复

**现象**：「立即购买」和「加入购物车」行为一致，都只是加购物车。

**根因**：`cartStore.cartItems` 返回顺序不确定，`cartItems[last].id` 可能不是最新添加的商品。

**修复**：
- `cart.js` — 购物车列表按 ID 倒序排列（最新在前）
- `ProductDetail.vue` — 立即购买取 `cartItems[0]`（最新项）→ 直接跳结算页

---

## 九、按钮防连点

**现象**：加入购物车、立即购买、秒杀等按钮可被快速连点，触发多次请求。

**修复**：新增 `useClickLock` 组合函数，点击后 500ms 内按钮自动禁用：
- `ProductDetail.vue` — 加入购物车 + 立即购买
- `SeckillDetail.vue` — 立即秒杀 + 确认秒杀

---

## 十、支付宝模拟支付自动降级

**现象**：选择支付宝支付时报 `RSA2签名遭遇异常，私钥不可为空`。

**根因**：服务器 `.env` 中支付宝密钥（`ALIPAY_APP_ID` 等）全部为空，`AlipayConfig.simulated` 默认 `false`，SDK 初始化时传空密钥崩溃。

**修复**：`AlipaySandboxStrategy.init()` — 自动检测空 appId 或空私钥时切换模拟模式。

---

## 十一、银联支付标记未开放

**现象**：微信支付显示"未开放"且禁用，银联却可选，点击报错。

**修复**：
- `OrderSettle.vue` — 银联加 `disabled` + `未开放` tag，支付宝排第一
- `SeckillDetail.vue` — 同上

## 经验总结

1. **nginx `try_files` 不处理 POST**：对非 GET 请求的 SPA 回退必须用 `proxy_pass`，不能依赖 `try_files`
2. **AI API 超时至少 30s**：DeepSeek 排序耗时长，15s 不够
3. **`watch(immediate:true)` + `onMounted` 会产生双重调用**：Vue 3 中这两个钩子互相独立，需避免重复逻辑
4. **支付宝 SDK 需要防御性初始化**：生产环境大多没配置真实密钥，自动降级到模拟模式
5. **Dubbo 与 Spring Cloud 注册名不能相同**：Gateway `lb://` 可能选中 Dubbo 端口导致 `PrematureClose`
