## 一、演示概览

```
JMeter 100 并发 → 秒杀接口 → Sentinel QPS=10 限流
                                    ↓
                         ~10 个请求成功（返回 state:200）
                         ~90 个请求被限流（返回"服务器忙"）
                                    ↓
                         SkyWalking 实时显示 QPS 尖峰 + 调用链拓扑
```

**截图点**：
1. Sentinel Dashboard — 流控规则触发，实时 QPS 曲线
2. SkyWalking 拓扑图 — mall-seckill 服务 QPS 从 0→100 的尖峰
3. SkyWalking 调用链 — 单个请求经过 Gateway → SSO → Seckill 的完整链路
4. JMeter 聚合报告 — 100 请求，~10 成功，~90 限流，吞吐量数据

## 三、配置 Sentinel 流控规则

启动 mall-seckill 后，先发一次正常请求让 Sentinel 感知到「秒杀订单提交」资源，然后在 Dashboard 中添加规则：

1. 打开 http://localhost:8090 → 左侧菜单「簇点链路」
2. 找到 `mall-seckill` 服务 → 资源名「秒杀订单提交」
3. 点击「流控」→ 新增流控规则：

| 配置项 | 值 |
|--------|-----|
| 资源名 | 秒杀订单提交 |
| 阈值类型 | QPS |
| QPS 阈值 | **10** |
| 流控模式 | 直接 |
| 流控效果 | **快速失败** |

> 提示：Dashboard 内存存储，重启后规则丢失。每次演示前需要重新配置。

## 五、测试计划说明

### 线程组设计

| 线程组 | 线程数 | 说明 |
|--------|--------|------|
| 前置-登录并获取随机码 | 1 | 登录获取 JWT → 获取秒杀 SPU 详情 → 提取 randCode |
| 主线程组-100并发秒杀下单 | 100 | 携带 JWT + randCode，1 秒内全部发起 |

### 请求流程

```
前置线程组（1 线程）:
  1. POST /user/sso/login     → 提取 Token
  2. GET  /seckill/spu/1       → 提取 randCode（来自 Redis）

主线程组（100 线程，1 秒爬坡）:
  3. POST /seckill/{randCode}  → 携带不同 contactName/mobilePhone
                                 （保证幂等性 Key 不同，全部通过幂等检查）
```

### 关键设计决策

- **为什么用 `${__threadNum}` 填充 contactName**：幂等性切面用 `MD5(userId + args)` 作为 Key。如果所有请求参数相同 → MD5 相同 → 幂等拦截。用不同参数确保每个请求通过幂等检查，让 Sentinel 真正发挥作用。
- **为什么 QPS=10**：秒杀是天然的限流场景，阈值不宜太高。10 QPS 足够展示"部分成功、部分限流"的效果。
- **为什么用 `__P()` 函数**：前置线程组通过 JSR223 将 Token/randCode 存为 JMeter 全局属性，主线程组通过 `__P()` 读取。

> "这是我做的秒杀压测演示。用 JMeter 模拟 100 个用户在同一秒内抢购秒杀商品。Sentinel 配置了 QPS=10 的流控规则，超过阈值的请求直接快速失败，返回'服务器忙'。从 SkyWalking 可以实时看到 mall-seckill 服务的 QPS 从 0 飙升到 100，但实际通过的只有 10 QPS——限流保护了后端数据库，防止了缓存击穿和库存超卖。"

## 八、故障排查

| 问题 | 原因 | 解决 |
|------|------|------|
| 所有请求都返回 401/403 | JWT Token 无效 | 确认 testuser1/123456 账号存在，SSO 服务已启动 |
| 所有请求都返回"重复提交" | 幂等 Key 冲突 | 确认请求体中的 contactName 使用了 `${__threadNum}` |
| randCode 提取失败返回 000000 | Redis 中没有随机码 | 确认 mall-seckill 启动时执行了 SeckillInitialJob，spuId=1 在秒杀窗口内 |
| 全部成功无限流 | Sentinel 规则未配置 | 在 Sentinel Dashboard 中为「秒杀订单提交」添加 QPS=10 流控规则 |
| Sentinel Dashboard 看不到服务 | 没流量经过 | 先手动发一次秒杀请求，Sentinel 才能感知到资源 |
| SkyWalking 看不到数据 | Agent 未挂载或 OAP 未启 | 确认 mall-seckill 的 VM options 包含 SkyWalking agent |
| JMeter 报 "内存不足" | 默认堆太小 | 修改 `jmeter.bat` 中 `HEAP=-Xms1g -Xmx2g` |
