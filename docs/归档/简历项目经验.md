## 项目一：CoolShark 微服务电商平台（主要项目）

**技术栈**：Java 21 / Spring Boot 3.2.5 / Spring Cloud Alibaba / Apache Dubbo 3.3 / MyBatis-Plus / Nacos / Seata / Sentinel / RabbitMQ / Elasticsearch / SkyWalking / MySQL / Redis / Vue 3 / Element Plus

**项目简介**：独立设计并开发的微服务电商平台，覆盖商品浏览、搜索、购物车、订单、支付、秒杀、AI 智能导购全链路，提供前后台两套系统；已通过 Docker Compose 部署至阿里云 ECS 并稳定运行。

**量化指标**：

| 指标 | 数值 |
|------|------|
| 微服务模块 | 11 个 |
| 数据库 / 表 | 6 库 / 39 表（业务 30）|
| 后端接口 | 45 个 Controller、554 个 Java 源文件 |
| 前端 | 32 个 Vue 页面、19 个 API 模块、29 条路由 |
| 容器化部署 | 21 个容器，4C16G 阿里云 ECS |
| 秒杀压测 | 100 并发验证（数据以视频重新录制为准） |

### S — 背景
从零构建一个生产可用的电商平台，作为校招主力项目展示微服务架构落地能力。

### T — 任务
独立完成全栈开发与部署，核心目标：
1. 微服务架构设计与服务拆分
2. 秒杀高并发场景的性能保障
3. 全文搜索与 AI 导购的智能化体验
4. 生产环境部署与运维调优

### A — 行动
1. **架构设计**：按领域拆分为商品、订单、秒杀、搜索、用户、权限、资源、AI 等 11 个服务，Dubbo RPC 服务间通信，Nacos 注册与配置中心，Gateway 统一路由与鉴权；
2. **秒杀高并发**：Redis 预扣库存 + RabbitMQ 异步落库削峰，SQL 条件扣减防超卖，Sentinel 限流熔断，Seata 分布式事务保证订单/库存一致性，幂等注解防重复提交；
3. **搜索与 AI**：基于 Elasticsearch + IK 分词实现全文搜索；AI 导购集成 DeepSeek 大模型，实现意图识别 → 查询扩展 → 多路召回 → 向量检索（BGE-M3）→ SSE 流式输出的 RAG 流水线；
4. **部署与调优**：Docker Compose 编排 21 个容器上云；JVM 调优（Seata/OAP 堆收缩 + 堆外内存限制）将内存占用 93% → 71%；独立定位并修复 ES 集群故障（IK 分词器丢失致集群 red）。

### R — 结果
- 秒杀接口通过 100 并发压测，Sentinel 限流规则生效，无超卖与重复订单
- 系统内存占用降低约 22%，可用内存 1.1G → 4.4G，稳定性显著提升
- ES 集群从 red 恢复至 green，搜索功能修复并完成 18 条商品数据同步
- 全链路接入 SkyWalking，实现跨服务调用链可视化追踪

## 项目二：智慧路灯 IoT 物联网管理平台（差异化项目）

**技术栈**：Java 17 / Spring Boot 3.4.3 / MyBatis-Plus / MQTT (EMQX) / TDengine / MySQL / Redis / JWT + RBAC / Vue 3 / ECharts / 高德地图 / MaxKB (RAG)

**项目简介**：面向市政道路照明的物联网管理系统，通过传感器采集环境数据、MQTT 远程通信、后端自动策略控制，实现路灯智能开关、调光、告警与能耗分析；已接入真实硬件（小熊派 BearPi）并完成移动端接口开发。

**量化指标**：

| 指标 | 数值 |
|------|------|
| 业务模块 | 16 个（设备/遥测/控制/告警/策略/能耗/AI助手/权限等） |
| 数据库 | MySQL 16 表 + TDengine 时序数据 |
| 后端接口 | 18 个 Controller |
| 前端页面 | 20+ 个（ECharts 图表、高德地图） |
| 移动端 | 33 个接口文档 |
| 权限体系 | 4 角色 × 17 权限码，48 个接口鉴权 |

### S — 背景
基于校企实训课题，构建一套从数据采集到智能决策的完整物联网平台，强调与电商项目差异化的工业落地能力。

### T — 任务
1. 设备 MQTT 接入与安全鉴权
2. 云端 + 边缘双层自动控制策略引擎
3. 时序数据存储与能耗分析
4. 多端（Web / 移动 / 硬件）协同

### A — 行动
1. **设备接入**：基于 EMQX 实现 MQTT 通信，设备独立凭据（BCrypt + AES-256 加密），ACL Topic 隔离，SSL 传输加密；
2. **双层决策引擎**：云端 DecisionEngine + 边缘 ConditionEvaluator（纯函数可迁移硬件），断网时本地自主决策；心跳离线检测 + 健康评分（四维度加权）；
3. **数据链路**：遥测数据经 MQTT → TDengine 时序库，能耗统计（节能率 / 碳减排）定时任务自动计算；
4. **AI 能力**：对接 MaxKB 知识库做 RAG 维修诊断，本地正则快匹 → AI 意图识别 → RAG 问答三段式流程，支持自然语言调参；
5. **多端协同**：Web 管理端 + 33 个移动端接口 + 真实硬件（小熊派）接入，端到端闭环。

### R — 结果
- 完整落地 4 角色 × 17 权限码 RBAC，48 个接口 + 16 条前端路由全面鉴权
- 边缘决策引擎与云端策略一致，断网自主控制；健康评分自动生成故障预警
- 真实硬件（小熊派）成功接入，数据采集 → 策略控制 → 能耗统计全链路跑通
- 解决 MaxKB 在 3.5G 低配 ECS 上的 OOM 死循环（内存限制 + 假 celery 替身方案）
