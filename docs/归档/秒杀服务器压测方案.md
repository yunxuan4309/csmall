**1. Sentinel Dashboard 端口修复（8090 之前打不开）**

- Nacos 配置内容：
  ```json

  ```

## 一、为什么要打服务器内部端口

```
本地压测 (公网):  本机 → 5M 带宽 → 服务器   ❌ 瓶颈是带宽,不是秒杀
服务器内部压测:   hey → localhost:10007    ✅ 纯测服务性能
```

打 `localhost:10007` 请求直接走服务器内网回环，绕开 5M 公网带宽，测的才是真正的服务能力。

## 二、压测链路全景

```
Python 脚本 (100 并发, 100个不同用户)
  → POST localhost:10007/seckill/{randCode}
    → Gateway? NO —— 直接打 mall-seckill 端口
    → Sentinel 限流 (QPS=10) → 超过返回"服务器忙,请稍后再试"
    → Redis 预扣库存 (校验 randCode)
    → RabbitMQ 异步消息 → 消费者落库
    → Seata 分布式事务
```

**注意**：压测直接打 `localhost:10007`（mall-seckill 内部端口），不经过 Gateway。因为 Gateway 也要解析 JWT，会多一层，且秒杀接口本身有 `@PreAuthorize("hasRole('user')")` 需要带 token。

### 压测工具选择

| 工具 | 状态 | 说明 |
|------|------|------|
| hey | ❌ 弃用 | 服务器无法访问 GitHub 下载（0 字节），且非必需 |
| Python 脚本 | ✅ 最终方案 | `deploy/jmeter/seckill_bench.py`，纯标准库，100% 可行 |

**为什么不用 JMeter**：JMeter 需要 500MB JVM，服务器内存紧张；且打公网受 5M 带宽限制，测的是网速不是服务。

### 压测脚本（seckill_bench.py）

```bash
# 用法（服务器上）
python3 /tmp/seckill_bench.py <randCode>

# 脚本自动完成：
# 1. 重置库存 mall:seckill:sku:stock:5 = 1000
# 2. 清理 100 个用户购买标记
# 3. 登录 benchuser01~100
# 4. 100 并发压测（每个用户 1 次）
```

**配套：批量注册用户脚本（create_bench_users.py）**
```bash
# 一次性注册 100 个用户 benchuser01~100 (密码 123456)
python3 /tmp/create_bench_users.py
```

## 三、前置数据准备

### 3.1 秒杀商品 & 随机码

随机码以 **Java 序列化**存于 Redis（`sr java.lang.Integer...`），无法直接 `redis-cli get`，必须走接口：

```bash
# 1. 获取秒杀列表（返回每个 SPU 的 url="/seckill/{randCode}"）
curl -s 'http://localhost:10007/seckill/spu/list' -H 'Authorization: Bearer <TOKEN>'
# 从返回里挑一个 SPU，记录它的 spuId 和 randCode
```

已确认的有效秒杀数据：

|--------|------|---------|------|
| 1 | 6999 | sku 1 | 49 |
| 2 | 5999 | sku 5 | 78 |

## 四、压测执行（Python 脚本方案）

### 4.1 压测脚本位置

| 脚本 | 位置 | 用途 |
|------|------|------|
| `seckill_bench.py` | 服务器 `/tmp/seckill_bench.py` | 100 用户并发压测 |
| `create_bench_users.py` | 服务器 `/tmp/create_bench_users.py` | 批量注册 100 个用户（一次性） |

### 4.2 执行压测

```bash
# 1. 同步脚本（从 ai-claude 家目录）
sudo cp /home/ai-claude/seckill_bench.py /tmp/seckill_bench.py

# 2. 确认 randCode（SPU2）
TOKEN=$(curl -s -X POST http://localhost:10009/user/sso/login -H "Content-Type: application/json" -d '{"username":"testuser2","password":"123456"}' | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['tokenValue'])")
RAND=$(curl -s http://localhost:10007/seckill/spu/2 -H "Authorization: Bearer $TOKEN" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d['data']['url'].split('/')[-1])")
echo "randCode: $RAND"

# 3. 压测（脚本自动重置库存+清标记+100用户登录）
python3 /tmp/seckill_bench.py "$RAND"
```

### 4.3 压测结果解读

```
成功下单:  8~36     ← Sentinel 放行的（QPS=10 限流下累计）
被限流:    64~90    ← Sentinel 拦截的（"服务器忙,请稍后再试"）
已购买拦截: ~0       ← 100 个不同用户，无重复购买干扰
```

**实测参考**（2026-08-06）：
- 压测 1：36 成功 / 64 限流（耗时 7.3s）
- 压测 2：8 成功 / 89 限流（耗时 12.3s）
- 差异原因：Sentinel QPS=10 是"每秒"阈值，压测持续时间不同导致累计成功数不同

**Sentinel 实时监控验证**：
```
秒杀订单提交:
  通过QPS = 10（正好等于限流阈值）
  拒绝QPS = 62（被拦截）
```

## 七、注意事项（重要！）

1. **库存有限**：SKU 库存只有 49/78/100 件，100 并发会快速扣完。录制前可用 SPU 3（库存 100），或压测后重置库存：
   ```bash
   docker exec csmall-redis redis-cli set mall:seckill:sku:stock:11 100
   docker exec csmall-mysql mysql -uroot -p"<pwd>" -e \
     "UPDATE cs_mall_seckill.seckill_sku SET seckill_stock=100 WHERE id=11;"
   ```

2. **内存紧张**：服务器可用仅 2.4G。压测前先 `free -h` 确认，hey 只占 ~10MB 安全。

3. **随机码有效期**：randCode 在 Redis 中 TTL 2 小时 5 分钟，过期后 `GET /seckill/spu/list` 会重新生成。

4. **失败率正常**：100 并发里 90 个被限流返回错误是**预期效果**，不是 bug。演示时话术要点明"这就是 Sentinel 在保护系统"。

5. **不要打公网**：`http://8.156.77.197/api/seckill/xxx` 会走 Nginx → 5M 带宽，压测结果失真。
