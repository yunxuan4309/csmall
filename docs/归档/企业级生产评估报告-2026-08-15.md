# CoolShark 企业级生产环境评估报告

> **评估日期**: 2026-08-15
> **评估范围**: 后端（mall-* 11 个微服务）、前端（csmall-vue）、服务器（8.156.77.197 Docker 集群）、AI 智能导购模块
> **评估方式**: 代码审计（本地仓库 + 公开 GitHub）+ 服务器实测（SSH 只读命令 + 容器/日志/Redis 检查）+ 联网核对行业基准（框架生命周期、安全实践）
> **评估目的**: 存档企业级生产就绪度基线，供后续整改参考（当前仅作演示/面试展示用，不承载真实生产流量）
> **关联文档**: `docs/项目上下文文档.md`、`TODO文件.md`、`docs/归档/Docker部署审计报告.md`

## 一、总体结论

| 评估面 | 评分（10 分制） | 一句话结论 |
|--------|:---:|------|
| 后端 | **6.0** | 架构骨架合格（微服务/事务/幂等/可观测性做对了），但 Spring Boot 已 EOL、JWT 密钥公开默认值、中间件零认证是上线硬伤 |
| 前端 | **5.5** | 分层清晰可用，但密码明文日志、无权限控制、零测试零 CI 阻塞生产 |
| 服务器/运维 | **4.0** | 运行稳定但零备份、无监控告警、内存紧张、应用容器无自愈 |
| AI 模块 | **专项状态** | 密钥泄露/免登录/漏记账问题已修复（2026-08-15），Sentinel 限流与预算时区待办 |

**总评**：项目**架构设计达到企业级水准**（微服务拆分、Dubbo RPC、Seata AT、Sentinel、SkyWalking、幂等防重、Flyway、统一异常/响应都做对了），但**安全与工程化成熟度不足**：JWT 密钥为公开默认值、中间件全部零认证、服务器零备份、无 HTTPS、前端密码明文日志、后端 CI 不跑测试、前端零测试零 Lint。当前状态**适合演示/内测，不建议直接承载真实生产流量**。好消息是大部分 P0 问题修复成本不高，属"补课即可上线"的类型。

## 二、后端评估（6.0 / 10）

### 2.1 亮点（企业级做对的部分）

| 项 | 说明 |
|----|------|
| 微服务架构 | 11 个微服务职责清晰（商品/订单/秒杀/搜索/AI 独立演进），Apache Dubbo 3.3.2 替代 Feign，服务间通过 Dubbo 接口消费 |
| 分布式事务 | Seata AT 模式 + 自定义 Dubbo Filter 修复官方 `dubbo-filter-seata` NPE bug |
| 幂等防重 | `@Idempotent` 注解 + Redis SETNX，覆盖下单/支付/秒杀核心链路（4 处） |
| 数据库治理 | Flyway 66 个迁移脚本版本化 6 库；全量审计 458 处 `#{}` 预编译、0 处 `${}` 注入风险；手机号 Jackson 自动脱敏（138\*\*\*\*5678） |
| 可观测性 | SkyWalking 全链路追踪 + Gateway traceId 全链路日志贯穿 + Actuator 健康检查 |
| 限流降级 | Sentinel 接入核心模块（登录/订单等 4 处 `@SentinelResource`），自定义 429 统一响应 |
| 统一工程 | 统一响应格式 `{state, message, data}`、全局异常处理器、Long→String 序列化防 JS 精度丢失 |
| AI 模块（2026-08-15 已修复） | 密钥治理（占位符化 + .env 隔离 + 服务器轮换）、`/ai/**` 强制登录、流式调用记账、客户端级预算强制检查 |

### 2.2 🔴 P0 —— 上线前必须处理

**P0-1. Spring Boot 3.2.5 已全面 EOL（无安全补丁）** ⭐最严重
- 依据 [endoflife.ai/spring-boot](https://endoflife.ai/spring-boot)：Spring Boot 3.2 系列 OSS 支持 **2024-12-31 终止**、商业支持 **2025-12-31 终止**，评估日已过 EOL **591 天**——已公开 CVE 永久无补丁，漏洞扫描器不会标记 EOL 漏洞累积，属于"公开、已评级、常被武器化、却无修复路径"的风险类。
- 连带老化组件：Spring Cloud Alibaba `2023.0.1.2`、Dubbo `3.3.2`、Nacos `2.5.2`、MyBatis-Plus `3.5.9`、Knife4j `4.5.0`。
- 升级方向：Spring Boot 3.3/3.4 + Spring Cloud Alibaba `2023.0.3.x`（版本对应见 [SCA 官方版本说明](https://sca.aliyun.com/docs/2023/overview/version-explain/)）；3.2→3.3 以依赖升级为主，需全量回归。

**P0-2. 生产 JWT_SECRET = 仓库公开默认值（可伪造任意 Token）**
- 实测 `/data/csmall/.env` 的 `JWT_SECRET=CooxiaoMall2026JwtSecretForHs512AlgorithmMustBeAtLeast64BytesLong`，与代码中默认值**逐字符相同**，而该默认值在公开 GitHub 仓库（`github.com/yunxuan4309/csmall`）可查。
- 后果：任何人可伪造任意用户（含 admin）的 HS512 JWT，登录鉴权形同虚设。
- 修复：生成 64 字节随机密钥，仅写入服务器 `.env`，代码默认值改为随机占位符。

**P0-3. 测试账号存在于生产库**
- `cs_mall_ums.ums_user` 中 `testuser1~testuser9` 均在，密码哈希与仓库 `database/init-test-data.sql` 一致（= **123456**，且文档公开写着）。任何知道该凭据的人可直接登录用户接口。
- 注：当前因"所有用户共享 2 元/日 AI 预算"有意保留用于测试，上线前必须清理或改密。

**P0-4. 中间件零认证**
- **Nacos 无认证**（实测匿名可访问 API）。Nacos 2.x 存在高危漏洞（如 Hessian 反序列化 RCE，见 [阿里云安全通告](https://help.aliyun.com/zh/acsg/nacos-high-risk-vulnerability)），应参照 [Nacos 官方安全最佳实践](https://nacos.io/blog/case-authorization/) 开启鉴权并仅内网暴露。
- **Elasticsearch 8.6 关闭 xpack 安全**（`xpack.security.enabled: "false"`），匿名可查全库数据。
- RabbitMQ 默认用户 `guest`（Docker 环境变量 `RABBITMQ_DEFAULT_USER=guest`）；Sentinel 控制台无鉴权。
- 目前唯一防线是阿里云安全组（文档声称仅开放 22/80/443），属单点防线，需实测验证（见服务器 P0-5）。

**P0-5. 两个仓库公开 + 密钥曾进 git 历史**
- 后端 `csmall` 与前端 `csmall-vue` 仓库均为 **public**。
- 真实 DeepSeek API Key 曾硬编码于 `application-test.yml` 并推送到 master（commit `719ff6f`，2026-07-18 引入），导致 2026-08 出现 deepseek-v4-pro 盗刷消费——已换新 key 并全部占位符化（commit `f0945c0`），但 **git 历史无法抹除**（除非 filter-repo 重写）；新 key 已实现"绝不入 git"。
- 建议：仓库转私有（或至少对新 key 严格不入库）；历史清理可选。

### 2.3 🟡 P1 —— 短期改善

- 网关无集中鉴权（各服务各自 SSOFilter 校验），无 token 撤销/黑名单（仅登出 Redis set）、无 refresh token；JWT 有效期 `604800s`（7 天）偏长。
- CORS 硬编码 5 个 origin（`CorsConfig.java`），换域名需改代码重编译。
- AI 接口无 Sentinel 限流规则（`sentinel-rules.json` 无 ai 条目）——已写入 `TODO文件.md`。
- 预算按 UTC 结算（每日预算在北京时间早 8 点重置，非零点）——已写入 `TODO文件.md`。
- 单测仅 8 个文件；**CI（`.github/workflows/ci.yml`）只执行 `mvn install -DskipTests`**——不跑测试、无 SonarQube、无 OWASP dependency-check、无制品推送。
- 分页字段 `list`/`records` 各服务不一致，前端手写兼容。

### 2.4 🟢 P2 —— 持续优化

- `application.yml` 硬编码 `spring.profiles.active: test`（Docker 部署用 `SPRING_PROFILES_ACTIVE=prod` 覆盖；本地裸跑有加载 test 配置/密钥占位符的误用风险）。
- 秒杀布隆过滤器仍未安装（当前数据量小，可接受）。
- 部分模块残留敏感配置默认值（如 `JWT_SECRET` 默认值、resource-host 默认 IP）。

## 三、服务器/运维评估（4.0 / 10）

> 全部数据来自 2026-08-15 服务器实测（ai-claude 账号只读检查）。

### 3.1 亮点

- 22 个 Docker 容器稳定运行 16 天，无异常重启；中间件全部配置健康检查；MySQL/ES/Redis/RabbitMQ 数据卷持久化。
- nginx 配置质量尚可：gzip、SSE 精确路径关缓冲、`/api/` 前缀剥离转发 Gateway、图片磁盘直出 + `expires 7d immutable`、SPA try_files 回退、`/admin/dashboard` Accept 分流。
- 权限收紧思路正确：ai-claude 独立账号 + sudoers 白名单（仅 systemctl/journalctl 免密）。

### 3.2 🔴 P0

**S-P0-1. 零备份** ⭐
- 实测无 `/data/backup` 目录、无任何 `.bak`/dump 文件。MySQL/ES/Redis 任一数据损坏 = 全部数据丢失。
- 修复：每日 `mysqldump`（6 库）+ `scp` 到本地留存 + 定期恢复演练（方案已在 `docs/评估报告/服务器权限收紧方案.md` 五-C2 中给出，未执行）。

**S-P0-2. 无 HTTPS**
- nginx 仅 `listen 80`，无 443/证书；登录密码、JWT、订单/收货地址全部明文过网。
- 已知阻塞链：HTTPS → SSL 证书 → 域名 → ICP 备案 → 服务器续费 ≥3 个月（8 月 29 日到期，见 TODO）。

**S-P0-3. 内存告急**
- 实测 `14Gi 总 / 12Gi 已用 / available 仅 2.2G`；4 核 16G 跑 21 容器。
- TOP 占用：skywalking-oap 1.08G、ES 1.04G、Nacos 979M、product 955M、seckill 796M、order 785M……任一突发即 OOM。
- 修复：给 ES/OAP/Nacos 加 `mem_limit` 硬限制，或升配。

**S-P0-4. 应用容器无 healthcheck + restart 策略混乱（崩溃不自愈）**
- 所有应用容器 `health=none`；restart 策略：`sso/gateway/ums/ams/ai = no`（崩溃后**不会自动拉起**）、`product/front/order/seckill/search = on-failure`、`resource = unless-stopped`。
- 修复：统一 `restart: unless-stopped` + 应用健康检查（如 `/actuator/health`）。

**S-P0-5. 中间件端口全绑 0.0.0.0，安全组是唯一防线（需实测）**
- `3306/6379/8848/9200/5672/15672/7091/8088/8090/11800/12800/10003~10010` 全部监听 0.0.0.0。
- 文档声称安全组仅开 22/80/443，但**必须从公网实测**（如手机 4G `telnet 8.156.77.197 3306`）确认；一旦安全组配置失误，MySQL/Redis/Nacos/ES 直接暴露公网。

### 3.3 🟡 P1

- **无监控告警**：无 Prometheus/Grafana/Alertmanager，仅 SkyWalking 追踪；磁盘满/内存 OOM/接口 5xx 无任何通知。
- **日志无轮转**：`json-file` 驱动无 logging 配置，日志无限增长（compose 中无 `logging:` 段）。
- 单机单点：无高可用、无跨机容灾；发布靠 scp 覆盖 jar + compose up，无自动回滚（手动恢复旧 jar 可行）。
- 镜像在服务器本地 build，无 CI 产物仓库/registry。

### 3.4 🟢 P2

- SSH 22 暴露公网、无 fail2ban；容器无资源 `limits`（单容器可吃满内存）；无域名（已知）。

## 四、前端评估（5.5 / 10）

> 依据 2026-08-15 前端仓库深度审计（子代理 + 主代理复核），证据含文件:行号。

### 4.1 ✅ 亮点

### 4.2 🔴 高严重度

| # | 问题 | 证据 |
|---|------|------|
| F-1 | **密码明文打印到控制台**（含登录响应与 token），任何共享电脑/浏览器插件/XSS 可读 | `src/store/frontUser.js:16-19,23` |

### 4.3 🟡 中严重度

- 主包 **1177KB** / CSS **355KB**：`main.js:2-4` 全量 `app.use(ElementPlus)` + `main.js:16-18` 循环注册全部图标；无 unplugin-auto-import/按需引入、无 `manualChunks` vendor 分包；`@nutui/nutui` 0 引用空依赖。
- 拦截器 reject 丢弃 `error.response`（`request.js:72,80`）→ `SeckillDetail.vue:857-868` 按 status 分支的错误处理**永不命中**；错误双弹窗。
- **零测试、零 ESLint/Prettier、零 CI、无 TypeScript**（`package.json` 无 test 脚本）。

- 无安全响应头（CSP/HSTS/X-Frame-Options/X-Content-Type-Options）；无 brotli；index.html 未设 no-cache。

### 4.4 🟢 低-中

- `cart.js:132` `totalPrice` `.toFixed(2)` 生成字符串被 `parseFloat` 消费，类型不一致。
- 图片无懒加载、无 WebP、无 CDN；`ProductDetail.vue:293` 用 `window.location.href` 整页跳转；`SeckillDetail.vue:878-884` 每秒整体替换对象触发全组件重渲染。
- 登录成功 `setTimeout 1000ms` 跳转（时序 hack）；无独立 404 页；`index.html` 无 SEO meta、`lang="en"`。

## 六、优先级路线图

### P0 —— 上线前止血（建议 1~2 周）

1. **JWT_SECRET 换随机强密钥**：生成 64 字节随机值 → 改服务器 `.env` → 重启 sso/网关/各服务。
2. **中间件认证加固**：Nacos 开启鉴权（`nacos.core.auth.enabled=true` + token）、ES 开 xpack、RabbitMQ 换专用强密码用户、确认安全组外网不可达。
3. **每日数据库备份**：`mysqldump` 6 库 + scp 本地 + 每周恢复演练。
4. **应用容器自愈**：统一 `restart: unless-stopped` + `/actuator/health` 健康检查。
5. **前端删密码日志**（`frontUser.js`）+ HTTPS 计划（域名/ICP 备案）。
6. **公网端口实测**：用外部网络验证安全组是否真的只开 22/80/443。

### P1 —— 短期改善（1 个月内）

7. **Spring Boot 3.3/3.4 + Spring Cloud Alibaba 2023.0.3.x 升级**（全量回归）。
8. **监控告警**：cAdvisor/Prometheus + 钉钉/邮件告警；日志轮转（`max-size`/`max-file`）。
9. **CI 完善**：跑单测 + OWASP dependency-check + 前端 lint/build/test。
10. **前端权限体系落地**（后端权限数据驱动菜单 + 路由守卫按角色过滤）+ 富文本 DOMPurify 消毒 + 支付表单改 iframe。
11. **内存治理**：ES/OAP/Nacos 加 `mem_limit`，评估升配。

### P2 —— 持续优化

12. 域名备案 + HTTPS + HSTS/CSP 安全头（前后端同时）。
