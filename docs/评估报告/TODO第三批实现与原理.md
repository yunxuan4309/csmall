## 六、第三批通用面试话术（贯穿主线）

**主线叙事（可直接背，约 300 字）**：

> "第三批我按'**先消雷 → 再做正确性前置 → 最后跨机**'的顺序推进。
> 先消两个运维雷：**nacos 重建就丢配置**（根因是没挂数据卷；实际修复时踩了个更隐蔽的坑——**卷名接错**，表现为登录报 `User nacos not found`），以及**备份从来没验证过**——我按'**备份没验证过就等于没有备份**'的标准，用**独立临时容器**做了一次完整恢复演练（先否掉第一版"直接在宿主机导入"的方案，因为它会**碰生产库**）。
> 然后做集群化的**正确性前置**：秒杀定时任务在多实例下会**双跑**（重试任务重复发 MQ、对账任务重复跑），所以加 Redis 分布式锁（SETNX + Lua CAS 释放 + finally 兜底）；它的验证我单独写了一篇——**'不重复'是观测不到的命题**，判据必须落在**失败方**，而且**验证脚本本身也会说谎**（TTL 断言用秒取整成 0，是脚本错了不是代码错了）。
> 最后是**跨机**：第一道坎不是业务，而是**"地址"的三重语义**——进程绑哪个网卡（`127.0.0.1` 跨机永远不通）、注册中心里别人看到的是**容器 IP** 还是**宿主机 IP**（跨机 Dubbo 挂掉的真正根因，要靠 `DUBBO_IP_TO_REGISTRY` 覆盖）、副本连中间件用的是**容器名**还是**内网 IP**。
> 通了之后，"集群"才谈得上被证明——我分别验了**负载均衡真的均分**（60 请求 → 30:30）、**故障转移真的自动**（选主 6.1s、客户端自愈 9.1s、数据零丢失）、**注册剔除真的有窗口**（客户端缓存导致 **16s** 内还会打过来）、**优雅下线真的零中断**（把 16s 窗口做成 0）。
> 最后我主动讲一个局限：**副本必须分布在'会独立故障的机器'上** —— 两台机器下 `min-replicas-to-write` 是**无解**的：要么某节点挂就不能写，要么允许静默丢数据；我把参数只开在主库侧、并留了演练开关，**接受这个局限但把它量化并写进文档**。"

**被追问"为什么只把这两个服务跨机"时**：秒杀是**演示价值最高**的（能同时看到负载均衡 + 故障剔除 + 限流规则热更新 + 定时任务锁），而**只有 seckill 有定时任务**（多实例改造点唯一）；商品/订单的收益/改动比更低（商品还要先改网关路由 `http→lb`）。

**被追问"这算高可用吗"时**（诚实边界）：跨机版**能防单机宕机**（老机挂时新机副本仍服务、Redis 主挂时哨兵切到新机从），但**不防地域灾难**，且其余 19 个容器仍是老机单实例 ⇒ 话术是"**验证机制**"，不是"高可用架构"；企业级做法（Testcontainers + 故障注入 + 指标断言 + CI 回归）我也讲得清。
