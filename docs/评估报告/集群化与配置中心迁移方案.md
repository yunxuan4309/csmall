## 一、背景与目标

当前单机部署 21 容器、每微服务 1 实例，配置分散在 `application-prod.yml` + compose 环境变量 + `.env` 三层。
为**模拟真实企业级场景**（面试价值），计划：

1. **集群化**：秒杀/订单/商品三模块各生成集群（每模块 ≥2 实例）
2. **配置中心**：几乎所有配置迁入 Nacos，验证集中管理 + 热更新

> ⚠️ 本方案**仅评估与计划**，暂不执行。所有步骤待用户择日实施。

## 三、评估结论

### 3.1 内存测算：加副本前必须先做 R7（单秒杀副本可行）

```
R7 释放（已定稿方案）: Nacos 976→512M 省 ~460M + Sentinel 限堆省 ~100M
→ available 2.1G + ~560M ≈ 2.66G

秒杀副本占用（-Xmx256m 压缩堆）: ~650M
→ 加副本后剩余 ~2.0G ✅ 余量充足
```

**结论（2026-08-26 已确认）**：**仅秒杀加 1 副本完全可行**，加完仍剩 ~2G 余量；
之前评估的"2~3 副本太紧"是基于商品+秒杀双副本，现仅取秒杀单副本，内存压力大幅缓解。

### 3.2 单机集群的边界（必须诚实）

- 单机多实例 = **演示级 HA**：可验证注册中心多实例、Gateway/Dubbo 负载均衡、配置中心热更新、故障剔除
- **机器宕机所有实例一起挂** → 真实企业级 HA 需 ≥2 台机器
- 面试定位："验证过集群机制" ✅ / "高可用" ❌

### 3.3 三模块集群价值对比（决定加不加副本）

| 维度 | 秒杀 seckill | 订单 order | 商品 product |
|---|---|---|---|
| 流量特征 | 高并发尖峰（但 QPS=10 限流压得很低） | 秒杀落库 + Seata 事务写 | 读多写少 |
| 当前 CPU | 3.89% | 3.63% | 3.76% |
| 定时任务 | ✅ MessageRetryTask 每5s → **需加分布式锁** | ❌ 无 | ❌ 无 |
| Dubbo 负载均衡 | 消费者侧天然支持 | 消费者侧天然支持 | 消费者侧天然支持 |
| Gateway 路由 | `lb://mall-seckill` ✅ 自动均衡 | `lb://mall-order` ✅ 自动均衡 | ⚠️ **`http://mall-product:9010` 直连非 lb，需改路由** |
| Sentinel 限流 | 每实例独立统计（副本后集群总量翻倍，要讲清） | 无 @SentinelResource 场景 | 无 |
| 改造成本 | **高**（定时任务锁） | 低 | 低（但要改 Gateway 路由） |
| 演示价值 | **最高**（秒杀压测看负载均衡 + 限流规则热更新） | 中（Seata 多实例验证） | 中（Dubbo provider 多接口均衡） |

**推荐（2026-08-26 已确认）**：
- **✅ 确认加副本：秒杀** —— 演示价值最高（秒杀压测看负载均衡 + 限流规则热更新），
  "定时任务分布式锁"是面试亮点；内存单副本充足
- **商品暂不加** —— 改造成本虽小，但 Gateway 路由 `http://mall-product:9010` 直连
  需改 `lb://` 才均衡，收益/改动比低于秒杀；内存也省下
- **订单暂不加** —— 事务核心，多实例 Seata 验证价值有，风险/收益比最低

## 四、方案设计（两阶段 + 前置）

### 阶段 A0：Nacos 认证开启（前置，2026-08-26 新增，待实施）

> **背景**：2026-08-26 实测 Nacos **完全无认证**（无 token 直接读配置返回 200、控制台免登录、默认账号 nacos 未改）。公网安全组只开 22/80 挡得住外部，但内网失陷后可无认证操作。**值得加**：成本低、生产化标配、面试必问，且与配置迁移同窗口执行（都要重启服务）。

**方案 A：最小可行认证（推荐）**
```
1. compose nacos environment 加：
   NACOS_AUTH_ENABLE: "true"
   NACOS_AUTH_TOKEN: <Base64 编码的 ≥32 字节随机串>   # 官方要求 ≥32 字节
   NACOS_AUTH_IDENTITY_KEY: serverIdentity
   NACOS_AUTH_IDENTITY_VALUE: <随机值>
2. 重启 nacos 容器 → 验证：无 token 访问 API 返回 403
3. 所有客户端同步配置（漏配 = 连不上 Nacos = 服务起不来）：
   - 11 个微服务：spring.cloud.nacos.discovery.username/password
     （Dubbo registry nacos:// 同样要配）
   - Seata：registry.nacos 段配 username/password
4. 验证：服务注册/发现正常 + Sentinel 规则仍能从 Nacos 拉取
```

> ⚠️ 坑：开认证是**全量同步变更**——11 微服务 + Seata + Dubbo 任一漏配，
> 该服务启动即失败。必须一个维护窗口内完成，先改配置再重启，不能分批。

**备选 B（不推荐单独用）**：8848 映射改 `127.0.0.1:8848:8848`（仅宿主机可达），
零成本但只挡外部，不解决"内网容器被攻破后无认证操作"。

### 阶段 A：配置中心迁移（先行，低风险）

**范围**（按用户决策）：非敏感配置全进 Nacos，敏感配置留 .env

| 进 Nacos（热更新） | 留 .env（不进 Nacos） |
|---|---|
| 数据源 URL / 连接池参数 | 数据库密码（MYSQL_PASSWORD） |
| Redis 地址 / 端口 | JWT_SECRET |
| RabbitMQ 地址 / 虚拟主机 | AI_API_KEY / EMBEDDING_API_KEY |
| Seata 事务组 / 协调器地址 | REDIS_PASSWORD |
| Sentinel 规则（已在此） | |
| 各业务开关 / 阈值 / 超时 | |

**实施步骤**：
1. 三模块（seckill/order/product）`pom.xml` 加 `spring-cloud-starter-alibaba-nacos-config`
2. 新建 `bootstrap.yml`（或 `spring.config.import`）：`server-addr` + `file-extension: yml`
3. Nacos 创建 dataId：`mall-seckill.yml` / `mall-order.yml` / `mall-product.yml`（group=DEFAULT_GROUP），内容为迁出的非敏感配置
4. 本地 `application-prod.yml` 中对应项删掉/保留默认值兜底（先保留，验证生效后再清理）
5. 需要热更新的 Bean 加 `@RefreshScope`
6. 验证：改 Nacos 配置 → 服务自动刷新（不重启）→ 确认生效
7. 验证回滚：Nacos 不可用时服务用本地兜底配置启动（nacos-config 有本地快照）

**坑**：
- 启动顺序：Nacos 必须先健康（compose 已有 `depends_on`）
- 敏感配置不回退：`${MYSQL_PASSWORD}` 占位符继续从环境变量取，与 Nacos 配置合并

### 阶段 B：集群化（配置中心验证后再做）

**拓扑（2026-08-26 已确认，仅秒杀 1 副本）**：

```
秒杀集群：csmall-seckill(10007) + csmall-seckill-2(10017)
商品、订单：保持单实例（暂不加副本）
```

**实施步骤**：
1. 先执行 R7 内存优化（Nacos 降堆 + Sentinel 限堆 + Swap 2G + mem_limit）
2. compose 复制 seckill 服务定义：新容器名 `csmall-seckill-2` + 新 HTTP 端口 10017；
   副本加 `JAVA_TOOL_OPTIONS -Xmx256m`
3. **seckill 定时任务分布式锁**（唯一硬改造）：
   - `MessageRetryTask` 加 Redis `SETNX lock`（如 `mall:task:retry-lock`，TTL 30s）→ 抢到锁才执行
   - 或引入 ShedLock 注解（更标准，但加依赖）
4. 验证：
   - Nacos 控制台看到 `mall-seckill` 2 实例
   - 压测秒杀 → SkyWalking/Gateway 日志确认请求分散到两实例
   - 停掉一个实例 → 流量自动切到另一个（故障剔除）
   - Nacos 改限流规则 → 两实例同时热更新
5. 回滚：停副本容器即可回到单实例

**坑**：
- Sentinel 限流按**实例**统计：副本后集群总 QPS = 每实例限流 × 实例数（QPS=10 × 2 = 20），面试要主动讲清
- Seata：多实例 + 同一 tx-service-group（csmall_group）无需改配置，undo_log 在 DB 天然多实例安全
- Redis 预扣 DECR 原子性：Redis 单实例共享，多实例无超卖风险
- MQ 消费：RabbitMQ 默认工作队列，消息只被一个实例消费（天然不重复）
- 商品 Gateway 路由 `http://mall-product:9010` 因商品未加副本，**无需改动**

## 五、风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 内存不足 OOM | 低（单副本） | 先 R7 + 副本压缩堆；仅加 1 副本，余量 ~2G |
| 定时任务重复执行 | 高 | Redis 分布式锁（先做） |
| Nacos 挂掉配置丢失 | 中 | nacos-config 本地快照兜底 + 敏感配置仍本地 |
| 限流语义变化（每实例） | 低 | 面试讲清，非 bug |
