## 五、常见疑问 FAQ（原 §七）


**Q1：手写会不会"重复造轮子"？**
A：不会。轮子（会话/预算/闸门/SSE/检索/降级）**都在项目里了**；新增的只有"工具契约 + 一次带 tools 的调用 + 循环"约 300 行，其中一半是 Schema 与工具。

**Q2：不上框架，将来要换模型供应商怎么办？**
A：`base-url` 已可配；DeepSeek 与硅基流动都是 **OpenAI 兼容协议**，换供应商是配置层的事。只有换**非兼容协议**才需要改客户端——而那时"档位 + 任务映射"的抽象仍在，改的是一处适配层。

**Q3：不用框架，参数校验/幻觉怎么办？**
A：**这两件事框架也不替你做**。参数靠 JSON Schema + **服务端二次校验**；幻觉靠"只把工具返回结果拼进上下文 + system 明确'只基于提供信息回答'"（项目 system prompt 已有此规则）。

**Q4：为什么工具轮要关掉思考？会不会变笨？**
A：工具选择是**结构化决策**，不需要长思考；关掉思考换来**稳定 JSON + 绕开 400 回传规则 + 省 token**。深度推理放在**最终生成轮**（`thinking: enabled`）。

**Q5：`mall-ai` 到底能不能落库做审计？**
A：**不能（现状）**——它没有任何数据库栈（无 JDBC/MyBatis/Flyway/`db/migration`）。所以审计落 **Redis List**；DB 化要给它引入整套持久化，与"无状态服务"定位冲突。

## 六、通用面试话术（本册主线，可直接背）

**主线叙事（约 350 字）**：

> "AI 这块我做了三件事：**选型、契约、可替换性**。
> **第一件是选型**：我要给导购加"让模型自己决定调哪个工具"的能力。当时所有人都说上 Spring AI。我没直接跟，而是先问'我到底缺什么' —— 结论是 **Agent 不是框架，是"一个循环 + 一份工具清单"**；然后我把候选方案逐条对比，最后**用一个决定性实测把结论钉死**：新框架的最低版本要求会**沿着继承链放大**——这个项目所有业务模块都继承同一个根 pom，所以'只影响 AI 模块'是错觉，实际是**全站升级**。引入依赖的代价不是"多一个 jar"，而是**整条继承链上的一次集体升级**。于是我的选择是**不引框架，手写薄编排**（约 300 行），并且写清了**诚实的代价**和**将来要换框架时的映射路径**。
> **第二件是契约**：模型侧不掌握在我们手里，所以我把'模型名、思考开关、工具与结构化输出互斥'这些**实测**成契约，做成**配置可配化**（档位 + 任务映射）—— 并且踩过一个隐式坑：**可配化必须用显式占位符**，隐式默认值会让'可配'静默失效。
> **第三件是可替换性**：我把 embedding 从'写死一家'改成可换，过程中发现两件更值钱的事 —— **"配置能改" ≠ "实现能换"**（业务代码还依赖具体实现类，缺的是接口 + 依赖倒置），以及**"写了 catch" ≠ "有降级"**（读码才发现**根本没有真正的降级链路**，补上之后才有）。顺带做了启动自检与维度校验，测试全绿。
> **最后我要主动说清楚'还没做的部分'**：模拟数据我只交付了第一层（造数 + 数据标识 + 可观测工具链）；**第二层'AI 并发压测'（mock LLM + Agent 双链路）还没开始**；向量检索的前置已全部解除，但**开关还没开、代码还没部署**。我不把这些说成'做完了'。"

**被追问"不用框架是不是重复造轮子"时**：轮子（会话 / 预算 / 并发闸门 / 流式 / 检索 / 降级）**项目里都有了**；新增的只有"工具契约 + 一次带 tools 的调用 + 循环" —— 而换来的是**不锁死版本、不被框架的迭代节奏绑架**，并且**升级路径是清晰的**（协议是 OpenAI 兼容，换供应商是配置层的事）。

**被追问"你怎么保证不是自嗨"时**（举证方式）：每一处结论都落到**实测**上 —— 影响面看**继承链 + 模块数**；契约看**最小请求实测**与**分片形状**；可替换性看**有没有注入点、有没有接口**；降级看**断掉外部依赖后接口是否真的返回兜底结果**。**"我以为"和"我实测"是两种东西。**

**被追问"你自己觉得哪里有风险"时**（诚实清单）：① **第二层并发压测没做**，所以"能扛多少并发"目前**没有真实数字**；② Embedding 加固的代码**未部署**；③ 跨机只覆盖了两个服务，其余仍是单机单实例 —— 演示级 HA，不是高可用架构。
