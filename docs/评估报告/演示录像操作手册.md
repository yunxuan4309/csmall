## 四、第 ① 档：浏览档（**pass 曲线**）—— 拍"流量变化"

### 4.1 操作

| 镜头 | 操作 | 时长 |
|---|---|---|
| 1 | **开始录屏**，先什么都不压 → 录**静默基线**（面板是一条贴地的平线） | **30~60s** |
| 2 | 新机会话执行下方命令 | 2~3 min |
| 3 | 镜头：**SkyWalking Load 曲线抬升** → 切 **Topology**（链路亮起）→ 切 **Sentinel 的 `mall-front` pass QPS** | 随压测 |
| 4 | **停压后别停录** → 录**曲线回落** → 打开 **Trace** 点开一笔请求看真实链路与耗时 | 30~60s |

```bash
python3 load_test.py --steps 20,50,100 --duration 45 --json ~/load_result.json
```

### 4.2 预期数字（2026-09-11 实测 · 可用来对镜头前的可信度）

| 并发 | RPS | p50 | p95 | p99 | 失败 |
|---|---|---|---|---|---|
| 20 | 69.0 | 278ms | 439ms | 539ms | 0 |
| 50 | 97.2 | 488ms | 817ms | 976ms | 0 |
| 100 | **99.6** | 796ms | 1995ms | **2466ms** | 0 |

### 4.3 💡 现场可讲的"拐点"（这是加分项）

- **20 → 50**：吞吐 **+41%**（69→97），**仍在增长**
- **50 → 100**：吞吐 **仅 +2.5%**（97.2→99.6，**饱和**），而 **p99 从 0.98s 涨到 2.47s（+153%）**
- ⇒ **吞吐上限 ≈100 req/s，拐点落在 50~100 并发之间** = 典型**排队饱和**
- 🔑 **判据**：`RPS 出现平台 + p99 陡增` 才是拐点；**本次全程 0 失败** → **只看成功率会误判成"系统还很闲"**

## 五、第 ② 档：限流档（**block 曲线**）—— 拍"限流生效"

### 5.1 为什么用"管理员登录"当靶子

| 靶子 | 规则 | 实测被限流 | 结论 |
|---|---|---|---|
| **`POST /admin/sso/login`**（假账号 `adminfake01`） | `adminLogin` QPS **10**（`mall-sso`） | **1259 次（93.26%）** | ✅ **用这个** |
| `POST /oms/order/pay` | `支付订单` QPS 20（`mall-order`） | 4 次（**0.66%**） | ❌ 压不出来 —— `@Idempotent` 切面在 Sentinel 之外先拦（583 次拿到 **409**） |

> 🔴 **必须讲对的一句话**：**被限流 = `state=429`**；**`409` 是 `@Idempotent` 的幂等锁，不是 block**（混起来会得出完全相反的结论）。

### 5.2 操作

| 镜头 | 操作 | 时长 |
|---|---|---|
| 5 | Sentinel 切到 **`adminLogin`** 资源的实时监控 | — |
| 6 | 新机会话执行下方命令 | 30~60s |
| 7 | 镜头对准 **block 曲线起来**（脚本日志同时滚出"被限流 93%"） | 随压测 |

```bash
python3 load_test.py --mode limit --target adminlogin --steps 20,40 --duration 30 --json ~/limit_result.json
```

**预期**：20 并发 → RPS **165.5**、**被限流 1259 次（93.26%）**、业务错误仅 `400`×91（假账号登录失败）

### 5.3 数据代价与清理（如实披露）

- ✅ **零业务数据**：假账号必然登录失败；**只有没被限流的请求才触达业务方法**
- ⚠️ 会在 `cs_mall_ams.ams_admin_login_log` 留下"失败的管理员登录尝试"日志（实测 8 秒约 **91 行**；**该表不属于 `data_source` 的 9 张表**）
- 🧹 可选清理：`DELETE FROM cs_mall_ams.ams_admin_login_log WHERE username = 'adminfake01';`
- 🎤 **话术**：坦诚说"我用一个假管理员账号把限流闸门压出来"——不装作是真实攻击

### 5.4 🆕 第三档：AI 档（`--mode ai`）—— **可选，且需生产变更，默认不录**

> ⚠️ 与前两档不同：AI 档**必须临时把模型出口指到内网 mock**（改生产），所以**不建议与浏览/限流两档混在同一次录制里**。

| # | 动作 | 命令要点 |
|---|---|---|
| 1 | **起 mock**（新机） | `python3 mock_llm.py --port 9999 --prompt-tokens 0 --completion-tokens 0` —— 🔴 **0 token** 是为了**不污染日预算记账**（否则约 5000 次调用就打满 2 元/天，之后每个请求都返回"服务繁忙"，与闸门满是同一句文案） |
| 2 | **挂 override**（老机） | `docker compose -f docker-compose.yml -f docker-compose.mock-llm.yml up -d mall-ai`（**先核对 override 里的 base-url = 新机内网**） |
| 3 | **放开入口限流** | Nacos `ai-chat` 阈值 5 → 200（**先把规则原文落盘 + 记 md5**；⚠️ 热改后**立刻 GET 可能读到旧快照**，等 1~2 秒再复核） |
| 4 | **压测** | `SIM_USER_PREFIX=testsimai python3 load_test.py --mode ai --link pipeline --users 800 --steps 20,50,100 --duration 45 --json ~/ai.json`（`--link agent` 再压一遍，两条链路**不混着讲**） |
| 5 | **恢复** | Nacos 改回 5 → 移除 override → `docker compose -f docker-compose.yml up -d mall-ai` → **验证 base-url 已回真实地址**（`docker inspect csmall-ai \| grep AI_API_BASE_URL`） |

**预期与结论（2026-09-12 实测）**：成功 RPS **pipeline 21.4 / agent ~20.4**；**20 并发档最健康**（p50 < 1s、首字延迟 100~170ms、0 硬失败）；两条链路**都在 50 并发开始被 AI 闸门（20）拒绝**。完整表 + "逐层找墙"（异步池 8 → AI 闸门 20）见 [[AI并发测试方案]] **§十**；执行记录（含 11 个问题与解决方案）见 [[TODO第三批实现与原理-2]]。

> 🔴 **录制时的两个读数陷阱（务必别讲错）**
> ① **"闸门满"与"真异常"客户端收到同一句文案**（`AI 服务暂时不可用，请稍后重试。`）⇒ 别在镜头前断言"这就是被闸门拒了"，除非同时打开**服务端日志** `grep '【AI并发闸门】'` 佐证；
> ② **总 RPS 会被毫秒级的快速失败抬高**（实测总 53.6 而成功仅 ~18/s）⇒ 讲承载**只看脚本打印的"成功 RPS"**。

## 七、⚠️ 常见疑问（录像时很可能被问）

| 疑问 | 答案（都实测过） |
|---|---|
| **面板里有的服务没曲线？** | 正常。**"注册到面板" ≠ "有数据"** —— 曲线只反映**流量**；压到就有。（🆕 2026-09-12 起 `mall-ai` 也有实测数据了：见 **§5.4 AI 档**） |
| **限流档为什么是 sso 的曲线？** | 因为靶子 `adminLogin` 属于 **`mall-sso`**。要 `mall-order` 的 block 得压 `新增订单`（**会真造订单**）或 `支付订单`（**实测压不出来**） |
| **网关的曲线呢？** | **`mall-gateway` 没有 Sentinel Gateway 集成**（jar 里无 `spring-cloud-alibaba-sentinel-gateway`，且它是 WebFlux）→ **它的路由从来不是 Sentinel 资源**。pass 曲线请用 `mall-front` |
| **SkyWalking 里 `mall-product` 看不到数据？** | 它的流量是 **Dubbo RPC**（端点名形如 `IForFrontSpuService.getSpuById`），**不产生 HTTP 端点曲线**；把**时间范围拉大**、或看 **Topology** 上 `mall-front → mall-product` 的连线 |
| **为什么要先录静默？** | 曲线要**有对比**才好看；没有基线，"起来"看不出来（§6.4） |
| **压测会不会伤生产？** | 浏览档**零写入**；限流档**零业务数据**（只写日志表）。脚本内置**安全阈值**：单档失败率超阈值自动中止该档 |
