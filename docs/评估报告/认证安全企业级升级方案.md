# 认证安全企业级升级方案

> **状态**: 评估 + 计划（2026-08-28），**待实施**（源自 05/06 面试准备讨论：BCrypt 是企业标准，但"哈希只是第一层"）
> **目标**: 把项目认证安全从"单层 BCrypt + JWT"向企业级生产靠拢——先列差距，再按优先级给建议

---

## 一、项目现有情况（已实现，代码实证）

| 层 | 现状 | 代码/证据 |
|----|------|-----------|
| 密码存储 | BCrypt 哈希 + 内置盐（10 服务统一）| `BCryptPasswordEncoder`：SSO SecurityBaseConfig / ums PasswordEncoderConfig / 7 个 ResourceWebSecurityConfiguration |
| 认证 | JWT 无状态 + HS512 + 69 字节密钥 | `JwtTokenUtils` |
| 登出 | Redis 黑名单（token_list_.lock）| 各模块 SSOFilter |
| 双体系 | 前台 mall_token / 后台 admin_token | 前端请求拦截器 |
| 权限 | 后台权限码 `hasAuthority('/ams/admin/read')` / C 端角色 `hasRole('user')` | @PreAuthorize 104 处 |
| 限流 | Sentinel 基础三件套（秒杀 QPS=10）| Nacos 规则 |
| 审计 | ams_login_log / ums_login_log 表 | Flyway ams V6 / ums V2 |
| 网关隔离 | 手写路由白名单，后台管理不对外 | `locator.enabled: false` |

## 二、没有实现的情况（差距清单）

| 层 | 企业级标准 | 你的差距 | 风险 |
|----|-----------|---------|------|
| 传输层 | HTTPS/TLS | 无域名未上 HTTPS（TODO #7 阻塞链：域名→备案→证书）| 密码明文过公网可被窃听（压测走内网掩盖了）|
| 防爆破 | 登录限流 + 账号锁定 + 验证码 | 只有 Sentinel 全局限流，**无按账号/IP 的登录限流** | 登录接口可被暴力撞库 |
| 密码策略 | 复杂度 + 弱密码黑名单 + 过期 | 无 | 123456 等弱密码 |
| 多因素 | MFA/2FA | 无 | 单因子，密码泄露即失守 |
| 算法演进 | Argon2id（内存困难型）或至少 cost 12+ | BCrypt 默认 cost=10 | 专用 FPGA/ASIC 可并行爆破 |
| 算法迁移 | DelegatingPasswordEncoder 多算法并存 | 单一 `new BCryptPasswordEncoder()` 无前缀 | 换算法必须全量重设密码 |
| 密钥管理 | 密钥轮换 + 版本化（kid）| JWT_SECRET 明文在 .env，无轮换机制 | 密钥泄露 = 全部 token 可伪造 |
| 风控 | 异常登录告警/设备管理 | 只有 login_log 表，无分析 | 被攻击无感知 |
| 会话 | 踢下线/多端管理 | 只有黑名单 | 无法管控被盗会话 |

## 三、建议（按优先级）

### 🔴 P0 低成本高收益（~1.5 人天，演示价值最高）
1. **登录限流**（按账号 + IP）：登录接口加 Redis 失败计数（如 5 次/分钟锁定 15 分钟）——复用现有 Redis + AOP/注解经验（参考 @Idempotent 实现），~0.5 天
2. **密码策略**：注册/改密强制复杂度（长度 ≥8 + 字符类型）+ 常见弱密码黑名单，~0.5 天
3. **DelegatingPasswordEncoder 化**：`{bcrypt}` 前缀多算法并存，为将来算法迁移铺路，现在改零风险，~0.5 天

### 🟠 P1 中等工作量（依赖外部条件）
4. **HTTPS**：先打通阻塞链（服务器续费 ≥3 个月 → 域名 ICP 备案 → Let's Encrypt + Nginx 443）
5. **Argon2id 切换**：新密码用 Argon2id（Spring Security 6.3+ 内置），老密码 bcrypt 验证 + 登录成功时平滑升级重存
6. **JWT 密钥版本化**：JWT 加 kid 头，支持定期轮换而不踢掉所有在线用户

### 🟡 P2 加分但演示价值低
7. **MFA**：登录二次验证（短信/OTP）
8. **风控告警**：login_log 分析（异地登录 / 频繁失败）→ 告警或锁定
9. **会话管理**：多端列表、远程踢下线

## 四、与面试的关系（诚实边界）

- **建议只做 P0 的 1–2 个**（登录限流 + 密码策略），面试能说"我有企业级认知且落地了"
- P0 之外的**讲认知即可**："我知道企业还有 MFA、风控、密钥轮换——我的项目是诚实边界，哈希只是第一层"
- **别为面试全做**：演示项目时间/收益不匹配，重点是能讲清楚差距和演进路径

## 五、实施顺序

```
P0-1 登录限流 → P0-2 密码策略 → P0-3 Delegating 化 → P1 按需（HTTPS 依赖域名/备案）
```
- P0 三项相互独立，可单独实施，不影响现有功能
- 每项改动都建议同维护窗口 + 回归登录/注册/支付链路
