## 一、目标与范围决策（用户 2026-08-26 已确认）

**目标**：把配置集中到 Nacos，验证**集中管理 + 热更新**（模拟真实企业级场景）。

**范围（按用户决策）**：**非敏感配置全进 Nacos，敏感配置留 `.env`**

| 进 Nacos（可热更新） | 留 .env（不进 Nacos） |
|---|---|
| 数据源 URL / 连接池参数 | 数据库密码（`MYSQL_PASSWORD`） |
| Redis 地址 / 端口 | `JWT_SECRET` |
| RabbitMQ 地址 / 虚拟主机 | `AI_API_KEY` / `EMBEDDING_API_KEY` |
| Seata 事务组 / 协调器地址 | `REDIS_PASSWORD` |
| Sentinel 规则（**已在此**） | |
| 各业务开关 / 阈值 / 超时 | |

> **现状注记**：**Sentinel 规则本就在 Nacos**（`deploy/docker/sentinel/` 为事实来源 → 发布到 Nacos），所以本次要迁的是**数据源 / Redis / MQ / Seata / 业务开关**这几类。

---

## 二、实施步骤（7 步）

1. 三模块（seckill / order / product）`pom.xml` 加 `spring-cloud-starter-alibaba-nacos-config`
2. 新建 `bootstrap.yml`（或 `spring.config.import`）：`server-addr` + `file-extension: yml`
3. Nacos 创建 dataId：`mall-seckill.yml` / `mall-order.yml` / `mall-product.yml`（group=`DEFAULT_GROUP`），内容为迁出的非敏感配置
4. 本地 `application-prod.yml` 中对应项删掉 / 保留默认值兜底（**先保留，验证生效后再清理**）
5. 需要热更新的 Bean 加 `@RefreshScope`
6. **验证正向**：改 Nacos 配置 → 服务自动刷新（不重启）→ 确认生效
7. **验证回滚**：Nacos 不可用时服务能用本地兜底配置启动（`nacos-config` 有本地快照）

> **顺序提示**：本篇实施**必须在集群化稳定之后**（集群化已完成）；若将来要给**跨机副本**也接配置中心，注意副本的 `server-addr` 必须指向**老机内网 IP**（副本不能再用容器名 `nacos`）。

---

## 三、两个坑（原方案实测记录）

1. **启动顺序**：Nacos 必须先健康（compose 已有 `depends_on`）；否则服务起不来。
2. **敏感配置不回退**：`${MYSQL_PASSWORD}` 这类占位符**继续从环境变量取**，与 Nacos 配置**合并**——不要把密码塞进 Nacos，也不要因为迁移而丢掉 env 取值路径。

---

## 四、验证与回滚

| 项 | 方法 | 通过标准 |
|---|---|---|
| 迁移生效 | 改 Nacos dataId 的一个可见项（如超时/开关） | 服务**不重启**即生效 |
| 兜底可用 | 临时停 Nacos（或断网）后重启服务 | 服务能用**本地快照/兜底配置**启动 |
| 回滚 | 删 `bootstrap.yml` 的 config 段 + 恢复 `application-prod.yml` 被删项 | 回到"compose env 注入"原行为，零数据风险 |

**回滚成本**：低（纯配置，不动数据、不动数据库）。
