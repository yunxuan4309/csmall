## 雪花 ID 速记（Q2）

```
结构：1符号 + 41时间戳 + 5数据中心 + 5机器 + 12序列(4096/ms)
为什么：分库后自增会重复 + 全局唯一 + 趋势递增
Long→String：JS Number 精度 53 位，19 位会丢 → Jackson 全局转
时钟回拨：MP 自带兜底（≤5ms sleep 重试，>5ms 抛异常）
workerId：MAC+进程号 hash 自动推导，零配置但集群可能撞
          扩展实例风险=workerId冲突(pid撞车+32桶hash)，解决=环境变量/ZK分配
系统表：flyway_schema_history（6库）+ undo_log（仅pms/oms/seckill=Seata痕迹）
Leaf（已弃用，JDK8 代差）：号段=DB批量发号内存递增（高吞吐，依赖DB）
             雪花=ZK分配workerId（集群唯一）+ 定时上报时间防回拨
选型：订单流水要严格递增→号段；要时间维度→雪花+ZK
```

## 冗余字段速记（Q3）

```
3 种类型：名称冗余（免JOIN）/ 计数冗余（免COUNT）/ 快照冗余（历史不被改）
6 张表：pms_spu(品牌名/分类名/销量/评论数) oms_order(地址快照)
        oms_order_item(标题/价格快照) oms_cart(商品信息)
        success(秒杀记录快照) 反例:seckill表不冗余
核心话术：空间换时间，快照换"数据历史一致性"（改价改地址不影响旧订单）
```

## Flyway 速记（Q5）

```
作用：数据库版本管理，启动自动执行未应用的 V{n}__xxx.sql
配置：baseline-on-migrate:true（旧库打基线跳过已有表）
范围：只管结构（所有迁移脚本=CREATE TABLE），数据走 database/*.sql 手动
分布：product V1~14 / order V1~5 / seckill V1~5 / ams V1~6 / ums V1~2 / resource V1
细节：undo_log 也是 Flyway 建的；已执行脚本有 checksum 不能改，只能加 V+n
边界：手动 ALTER 检测不到（checksum 只校验脚本不校验库）→ 环境漂移
     规范：结构变更一律走 Flyway 脚本；已手动改则补幂等 V+n 登记
```

## 连接池速记（Q7）

```
现状：resource=HikariCP（事故后换），其余6服务=Druid 稳定；长期统一 HikariCP
事故4层链：并发占满池(maxActive=8) → max-wait=0无限等(线程挂死/雪崩)
          → 普通版druid配置不生效(druid.* 需 starter版) → HikariCP connection-timeout 10s 快速失败
要点：Druid starter=配置生效+监控面板(免费)；SkyWalking 已覆盖监控→不用 Druid
参数：connection-timeout 10s / max-lifetime 5min(防 MySQL 8h 断连)
```

## 分页转VO速记（Q9）

```
泛型擦除：IPage<Model> 强转 IPage<VO> 编译过但运行 ClassCastException
正确做法：stream+convertToVO+new Page<VO>，setRecords 塞转换后的 List
为什么不统一：实体=数据库镜子(全字段,CRUD载体)，VO=前端菜单(展示字段)
             一个实体→多个VO(详情/列表)；写操作必须实体
两种风格共存：BaseMapper内置方法=泛型写死实体→只能返回实体(框架不认识VO)
             自定义XML resultMap=VO→直接造VO(只读)；简单查询用前者，复杂用后者
```
