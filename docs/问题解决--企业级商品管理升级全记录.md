# 问题解决：企业级商品管理升级全记录

> **日期**：2026-08-03 ~ 2026-08-04
> **范围**：从基础 CRUD 修复到企业级属性模板/SKU 管理/相册系统的全量升级过程
> **关联文档**：`企业级商品管理升级计划.md`、`企业级商品管理升级--测试建议.md`、`数据库Schema漂移审计.md`

---

## 一、升级背景

商品管理模块原有功能仅为 SPU 级别的基础增删改查（含占位按钮），缺乏：
1. 属性模板与属性数据的管理
2. SKU 级别的完整管理（生成/增删改/图片）
3. SKU 与属性模板的联动
4. 相册图片管理体系

代码层面存在大量历史遗留问题：`useGeneratedKeys` 隐患、`spuQuery.xxx` 前缀错误、列名不一致、`@RequestBody` 缺失等。

## 二、阶段一：SPU 基础 CRUD 修复（2026-08-03）

### 2.1 新增商品失败：`Field 'id' doesn't have a default value`

**现象**：新增商品时 SpuDetail 插入报错 "Field 'id' doesn't have a default value"

**根因**：`SpuDetailMapper.xml` 的 insert 用了 `useGeneratedKeys="true" keyProperty="id"`（依赖数据库自增），但 `pms_spu_detail.id` 是雪花 ID 非自增。同时 `addNew` 方法里 `SpuDetail` 没设置 id。

**解决**：XML 改为显式插 `id` 列（`#{id}`）+ Service 层 `spuDetail.setId(IdWorker.getId())`。

### 2.2 SpuMapper insert/update 的 `spuQuery.xxx` 前缀错误

**现象**：新增/编辑保存报 "There is no getter for property named 'spuQuery' in 'class Spu'"

**根因**：`SpuMapper.xml` 的 insert VALUES 和 update SET 中多处用了 `#{spuQuery.xxx}`（参数是 Spu 实体，不是 SpuQuery），MyBatis 绑定参数时找不到 `getSpuQuery()`。

**解决**：insert 块 5 处 `spuQuery.typeNumber/brandId/categoryId/published/checked` → 改为实体属性名；update 块 5 处同样修复。`updateCheckedById` 的 `#{spuQuery.checked}` → `#{checked}`（审核功能一并修复）。

### 2.3 编辑保存 "SQL String cannot be empty"

**现象**：编辑商品时报 "SQL String cannot be empty"

**根因**：`SpuServiceImpl.updateById` 里 `spu.setId(id)` 缺失 → id=null → update XML 的 `<if test="id != null">` 为假 → 整个 UPDATE 被跳过 → 生成空 SQL。同时 SpuUpdateDTO 缺 `listPrice/pictures/stock/unit/keywords/tags` 字段。

**解决**：补 `spu.setId(id)` + SpuUpdateDTO 补 7 个字段 + 前端编辑 payload 同步。

### 2.4 上传图片 404

**现象**：新增时图片上传 404 "服务器忙"

**根因**：① vite.config.js 代理缺 `/upload`（只有 `/resource`）② 本地 resource 配置上传目录为 `E:/csmall-upload`，用户没有 E 盘 → 写入失败。

**解决**：vite 补 `/upload` 代理 + 上传目录改为 `D:/java/csmall/csmall-upload`（项目内目录，加入 .gitignore）。

### 2.5 编辑标题报"必须2~16字符"

**现象**：编辑保存报 "标题名称必须由2~16字符组成"

**根因**：`SpuRegExpression` 标题正则 `.{2,16}` 太严，现有商品标题普遍超 16 字。

**解决**：改为 `.{2,100}`，SkuRegExpression 同步修改。

### 2.6 库存预警阈值必须 1~999999

**现象**：新增商品报 "库存预警阈值必须是1~999999的值！"

**根因**：`SpuAddNewDTO` 的 `stock/stockThreshold` 有 `@Range(min=1)`，但表单默认值是 0。

**解决**：前端 stock/stockThreshold 默认值改为 1，el-input-number `:min` 对齐。

### 2.7 相册格式错误

**现象**：新增报 "选择的相册的数据格式错误"

**根因**：`SpuAddNewDTO.albumId` 有 `@Min(1)`，但相册表为空（没有合法相册 ID）。

**解决**：`albumId` 的 `@Min(1)`→`@Min(0)`（0=未关联相册，相册系统休眠期间的临时处理）。

## 三、阶段二：属性模板/SKU 体系修复（2026-08-03）

### 3.1 属性模板列表报错：`Unknown column 'pinyin'`

**现象**：进入商品列表即报错 "Unknown column 'pinyin' in 'field list'"，查询 `pms_attribute_template` 失败

**根因**：实体 `AttributeTemplate.java` 有 `pinyin` 字段，但数据库（本地和服务器都）没有这列。MyBatis-Plus 自动查询带出 pinyin → 报错。

**排查过程**：错误是在模板列表查询时触发的——进入 SpuList 时 `loadOptions` 调用 `getAttributeTemplateList` → BaseMapper SELECT 实体全字段 → 表缺 `pinyin` → 报错。

**解决**：按用户原则"优先补数据库列而非删实体字段"，本地/服务器 `ALTER pms_attribute_template ADD COLUMN pinyin varchar(64)`。同时发现还需补 `keywords` 和 `sort` 列，一并修复。

**经验教训**：实体-DB 字段不匹配 → 优先 `ALTER` 补列，不要删除实体字段（字段代表设计意图，pinyin 对 Brand 已实际使用，模板保留同样有价值）。

### 3.2 属性模板详情报错：`Unknown column 'pms_attribute.template_id'`

**现象**：生成 SKU 时加载属性模板报错 "Unknown column 'pms_attribute.template_id' in 'on clause'"

**根因**：`AttributeTemplateMapper.xml` 的 JOIN 里 `pms_attribute_template.id=pms_attribute.template_id` 没改——我在修 `AttributeMapper.xml` 的 `template_id→attribute_template_id` 时**漏了 AttributeTemplateMapper.xml**。

**解决**：2 处 `pms_attribute.template_id` → `pms_attribute.attribute_template_id`。全项目搜索 confirm 无残留。

### 3.3 生成 SKU 时规格明细插入失败：`Field 'id' doesn't have a default value`

**现象**：生成 SKU 时报 "Field 'id' doesn't have a default value"，日志显示 `insert into pms_sku_specification (sku_id, attribute_id, ...)` 不带 id 列

**根因**：`SkuSpecificationMapper.xml` 的 `insertBatch` 用了 `useGeneratedKeys="true" keyProperty="id"`（依赖数据库自增），但 `pms_sku_specification.id` 是雪花 ID 非自增。且 Service 层 `generateSkus` 里给 SkuSpecification 设了 id 但 XML 不插它。

**解决**：XML insertBatch 改为显式插 `id/sort`（`#{item.id}, #{item.sort}`），去掉 useGeneratedKeys。

### 3.4 SKU 编辑保存报错：库存/阈值必须 1~999999

**现象**：修改 SKU 价格/库存时报 "库存预警阈值必须是1~999999的值！"

**根因**：`SkuUpdateFullInfoDTO` 的 `stock/stockThreshold` 是 `@Range(min=1)`，但生成 SKU 时默认值是 0，前端保存时传 0 → 后端校验拒绝。

**解决**：`@Range(min=0)` 允许 0 库存。因为刚生成的 SKU 库存就是 0，管理员后续再填。

### 3.5 `SkuSpecification.id` 类型错误：Integer vs Long

**现象**：编译失败 "long 无法转换为 java.lang.Integer"

**根因**：`SkuSpecification.id` 声明为 **Integer**（雪花 ID 是 19 位 long，用 Integer 存不下）。且 `generateSkus` 里 `spec.setId(IdWorker.getId())` 返回 long → 无法赋值 Integer。

**解决**：实体 `id` Integer→**Long**。同时 `SkuSpecificationStandardVO.id` 同样改为 Long。数据库 `pms_sku_specification.id` 原本就是 bigint（正确）。

### 3.6 8 个 mapper 的 useGeneratedKeys 隐患统一修复

**现象**：SpuDetail/SkuSpecification 的 `Field 'id' doesn't have a default value` 问题会扩散到其余 mapper

**根因**：mall-product 有 9 个 mapper 的 insert 依赖 `useGeneratedKeys`（数据库自增），但项目是雪花 ID → 所有表的 id 列都非自增。已暴露的是 SpuDetail 和 SkuSpecification，其余 7 个（Album/Brand/Category/Attribute/AttributeTemplate/BrandCategory/CategoryAttributeTemplate/Picture）迟早也会炸。

**排查过程**：全项目搜索 `useGeneratedKeys`，找到 9 个 mapper → 逐一改为显式插 `id` 列（`#{id}`）→ 各 Service 的 addNew 补 `setId(IdWorker.getId())` → full clean compile 确认。

**解决**：
- 9 个 mapper XML：去掉 `useGeneratedKeys`，列和值各加 `id`
- 8 个 Service（Album/Brand/Category/Attribute/AttributeTemplate/BrandCategory/Picture/SkuSpecification）：addNew 前 `setId(IdWorker.getId())`
- 全项目复查确认无残留（OmsCart 的 `saveCart` 是死方法，BaseMapper.insert 自动雪花 ID 正常）

## 四、阶段三：属性模板/属性数据模型对齐（2026-08-03）

### 4.1 属性模型两套设计冲突

**现象**：`pms_attribute` 的 DDL（`id/attribute_template_id/name/type/values`）与实体 `Attribute.java`（`id/templateId/name/description/type/inputType/valueList/unit/allowCustomize`）是两套完全不同的设计

**根因**：
- DDL/库 = 属性值存储模型（`values` 直接存值列表）
- 实体 = 属性定义模型（有类型/输入类型/可选值/单位/是否可自定义）

**解决**（选属性定义模型 A，以实体为准）：
- `pms_attribute` ALTER 补 `description/inputType/valueList/unit/isAllowCustomize` 5 列
- `Attribute.java`：`templateId` 加 `@TableField("attribute_template_id")`，`allowCustomize` 加 `@TableField("is_allow_customize")`
- `AttributeMapper.xml`：所有 `template_id` → `attribute_template_id`（解决 BaseMapper Unknown column 隐患）
- `pms_attribute.sql` DDL 同步

### 4.2 `pms_sku_specification` 表结构漂移

**现象**：SkuSpecification 实体有 `attributeName/attributeValue/unit/sort`，数据库没有这些列；数据库有 `attribute_value_id`（NOT NULL），实体没有。

**解决**：库补 `attribute_name/attribute_value/unit/sort` + `attribute_value_id` 改可空。

### 4.3 `pms_category_attribute_template` 关联数据缺失

**现象**：模板存在但未被任何分类关联（新增模板时可关联）

**解决**：插入 3 条关联（手机→模板1、笔记本→模板2、男装→模板3）

## 五、阶段四：完整 SKU 管理与换模板保护（2026-08-04）

### 5.1 换模板后旧 SKU 残留

**现象**：编辑商品换属性模板后，旧模板生成的 SKU 仍然存在，造成数据不一致

**解决**：`SpuServiceImpl.updateById` 检测模板变更 → 删除该 SPU 下所有旧 SKU + 删除对应规格明细。新增 `SkuMapper.deleteBySpuId` + `SkuSpecificationMapper.deleteBySkuIds`。

**配套前端保护**：编辑弹窗检测到模板变更 → 弹 10s 倒计时警告（"更换模板将删除该商品下所有已生成的 SKU 及规格数据"），倒计时内确认被拒，防止误操作。

### 5.2 SKU 无图片管理

**现象**：SKU 生成后 pictures 为空，无法为 SKU 上传独立图片

**解决**：SkuManage.vue 加图片上传列（`el-upload` 点图上传 → 调用 uploadFile → toRelativePath 转相对路径 → 更新 SKU pictures）。

### 5.3 SKU 无单个增删

**现象**：只能批量生成，不能手动新增/删除单个 SKU

**解决**：
- 后端：新增 `POST /pms/sku/{id}/delete` 端点 + `ISkuService.deleteById`（删 SKU + 规格）
- 前端：新增 SKU 弹窗（标题/价格/库存/条形码）+ 删除按钮

### 5.4 AttributeController/AttributeTemplateController 缺 @RequestBody

**现象**：POST 端点未标注 `@RequestBody`，用 JSON body 提交会绑定失败

**解决**：addNew/updateById 方法参数加 `@RequestBody`。

## 六、经验总结

### 高频问题模式

1. **useGeneratedKeys + 雪花 ID 冲突**——9 个 mapper 有同样隐患，逐个暴露
2. **实体字段与数据库列不同步**——`template_id` vs `attribute_template_id`、缺列、`spuQuery` 前缀
3. **`@RequestBody` 缺失**——历史遗留，本次补了 2 个 Controller
4. **校验 `@Range(min=1)` 与业务默认值 0 冲突**——SpuAddNewDTO/SkuUpdateFullInfoDTO 的库存字段

### 运维教训

1. **实体-DB 字段不匹配 → 优先 ALTER 补列**（不能删实体字段）
2. **全项目搜索替代逐点修复**——useGeneratedKeys / spuQuery / template_id 此类问题应一次性全局排查
3. **编译错误是好事**——暴露了 `SkuSpecification.id Integer`（雪花 ID 溢出）
4. **Flyway 迁移与实体演进必须同步**——否则 database/ 建表脚本会误导

## 七、雪花 ID JavaScript 精度丢失（2026-08-04）

### 7.1 模板 ID/SPU ID 截断 → 404

**现象**：管理模板属性/生成 SKU 时报 "数据不存在"，日志显示后端收到的 ID 与数据库不符

| 数据库 | 前端传给后端 | 差异 |
|--------|------------|------|
| 2084296453980209**154** | 2084296453980209**200** | 末 3 位被截断 |
| 2084505101985701**890** | 2084505101985702**000** | 末 3 位被截断 |

**根因链**：`BeanFactory` 定义了裸 `new ObjectMapper()` Bean → 覆盖了 Spring Boot 默认 → `JacksonConfiguration` 的 `Jackson2ObjectMapperBuilderCustomizer`（Long→String）失效 → JSON 中 ID 为数字 → JavaScript `JSON.parse` 超 16 位安全整数 → 末 3 位四舍五入 → 前端拿到错的 ID → 404。

另外 `SkuManage.vue` 有 `Number(route.params.spuId)` 将字符串 ID 二次转回数字，导致即使后端修复后仍然截断。

**解决**：
- `BeanFactory.objectMapper()` 删除（回归 Spring Boot 默认，Long→String 生效）
- `SkuManage.vue` 删除 `Number()` 转换（直接使用 String）
- `JacksonConfig`（mall-sso）补 `ToStringSerializer` for Long
- 前端图片 URL 统一使用 `buildImageUrl()`（`VITE_RESOURCE_HOST`），不用 `window.location.origin`

### 7.2 模板详情列名冲突（attribute_template vs attribute）

**现象**：属性列表显示模板名而非属性名，输入类型显示"未知"

**根因**：`AttributeTemplateMapper.xml` 的 `DetailsQueryFields` 中模板列（`id, name, sort`）和属性列同名，resultMap 无别名区分 → MyBatis 取错值

**解决**：属性列加 `attr_` 别名前缀（`pms_attribute.id AS attr_id` 等），resultMap collection 同步使用别名。

## 八、品牌管理完整升级（2026-08-04）

### 8.1 品牌 Logo 不显示

**现象**：所有品牌 `logo=NULL`，即使有也因 `row.logo` 裸相对路径不拼接资源前缀 → 浏览器请求到错误地址

**解决**：和商品图片一样，统一使用 `buildImageUrl()` 拼 `VITE_RESOURCE_HOST`

### 8.2 BrandController addNew/updateById 缺 @RequestBody

**现象**：新增/编辑品牌时所有字段绑定为 null → 抛出 "请填写名称/拼音/Logo/简介/关键词！"

**根因**：`@Valid BrandAddNewDTO` 缺 `@RequestBody` → Spring 无法从 JSON body 绑定参数

**解决**：addNew + updateById 均补 `@RequestBody`

### 8.3 BrandAddNewDTO/BrandUpdateDTO 冗余 @NotNull

**现象**：去掉 @NotNull 后仍报 "名称的拼音必须由2~50字符组成！"

**根因**：前端传空字符串 `""` → `@Pattern([a-zA-Z\\s]{2,50})` 要求 2~50 字符不满足

**解决**：
- `BrandRegExpression.REGEXP_PINYIN` 改为 `(?:|[a-zA-Z\\s]{2,50})`（允许空，与 AttributeTemplate 一致）
- 去 `pinyin/logo/description/keywords/enable` 的 `@NotNull`
- 仅保留 `name` 必填

### 8.4 品牌删除保护

**现状**：`BrandServiceImpl.deleteById` 已调用 `spuMapper.countByBrandId(id)`，有关联 SPU 时拒绝删除 → **无需修复**。

## 九、SKU 管理完善（2026-08-04）

### 9.1 SKU 编辑保存不传 pictures/title

**现象**：SKU 上传图片后刷新丢失

**根因**：`saveSku` 只发 `{price,stock,stockThreshold,sort}`，没发 `pictures/title`

**解决**：补 `title` 和 `pictures` 字段

### 9.2 SKU 新增校验过严

**现象**：新增 SKU 报 "相册格式错误"、"条型码长度"、"库存阈值 1~999999"

**解决**：
- `albumId` `@Min(0)`（允许 0，相册未启用）
- `barCode` `.{0,16}`（允许空）
- `stockThreshold` `@Range(min=0)`

### 9.3 库存自动同步

**现象**：所有 SPU 的 `stock` 与 `SUM(SKU stock)` 不一致（差距 10~120）

**解决**：
- `SkuServiceImpl` 新增 `syncSpuStock` 方法，在 `addNew/generateSkus/updateFullInfoById/deleteById` 后自动调用 `spuService.synchroniseStock`
- 数据库一次性修正：`UPDATE pms_spu SET stock = (SELECT SUM(...) FROM pms_sku WHERE ...)`

### 9.4 前台 SKU 图片联动 + 无库存置灰

**现象**：选 SKU 后商品主图不切换，库存为 0 的 SKU 仍可点击

**解决**：
- `selectSku` 检查 SKU `pictures` JSON → 有图切主图，无图保持 SPU 图
- `stock≤0` → `sold-out` 类（opacity 0.45 + 不可点击 + "已售罄"）
- 修复 `mainPicture` 字段名错误（`SkuStandardVO` 无此字段，应解析 `pictures` JSON）

## 十一、分类管理 + 订单状态管理（2026-08-04）

### 11.1 分类编辑缺 @RequestBody + @NotNull 冗余

**现象**：编辑分类保存报 5 个字段 "NotNull" 错误

**根因**：`CategoryUpdateFullInfoDTO` 的 `icon/keywords/enable/display` 有 `@NotNull`，且 `CategoryController.updateById` 缺 `@RequestBody`

**解决**：补 `@RequestBody` + 去 4 个字段的 `@NotNull`（仅保留 name）。`CategoryAddNewDTO` 同步修复。

### 11.2 管理员/角色/权限页去占位按钮

**现象**：三个管理系统页面显示"功能开发中"占位按钮，影响体验

**解决**：删除所有操作列和新增按钮，改为只读列表 + 提示"系统管理数据由数据库直接维护"

### 11.3 订单状态管理（正向流转 + 管理员特权）

**现象**：后台"发货"按钮无法使用，需改为状态管理

**解决**：
- 后端 `updateOrderState`：`@PreAuthorize("isAuthenticated()")` + 内部 `isCurrentUserAdmin()` 判断 + 正向流转校验 `isValidStateTransition()`
- 前端 AdminOrderList.vue："发货"→"状态管理"弹窗（下拉合法目标状态 → 确认修改）
- 管理员可操作任意订单 + 任意流转；普通用户仅自己订单 + 正向流转

### 11.4 `hasRole` 全项目审计

**发现**：管理员 JWT authorities 不含 `ROLE_admin` 前缀 → 所有 `hasRole('admin')` 均失效。`hasRole('user')` 仅前台用户 token 生效（`UserUserDetails` 硬编码了 `ROLE_user`）

**修复**：
- `OmsOrderController.updateOrderState`：`hasRole('user')` → `isAuthenticated()`
- `SeckillManageController` ×4：`hasRole('admin')` → `isAuthenticated()`
- 其余 `hasRole('user')`（购物车/下单/支付/用户功能）保留——管理员不需要这些前端用户操作

### 11.5 其余 Controller @RequestBody 补漏

**审计发现**：`AlbumController`(×2)、`CategoryController`(×2)、`PictureController`(×1) 仍缺 `@RequestBody`。虽当前未启用但统一补齐，避免未来踩坑。

### 11.6 订单状态 0 被 JS falsy 误判

**现象**：状态 0="未支付"（合法值），`if (!stateForm.newState)` 中 `!0=true` → 误报"请选择目标状态"

**解决**：改为 `== null` 判断
