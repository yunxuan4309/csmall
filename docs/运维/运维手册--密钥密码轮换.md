## 〇、三者核心区别（先看这张表）

| | JWT_SECRET | MySQL root 密码 | Redis 密码 |
|---|---|---|---|
| 换完影响 | **全员重新登录**（旧 token 全失效） | 无感（DB 服务重建时切换） | 无感（重建时切换） |
| 涉及重建 | 11 个微服务 | 7 个连 DB 服务 | redis + 11 个微服务 |
| 是否 restart 就生效 | ❌ 必须 recreate | ❌ 必须 recreate | ❌ 必须 recreate |
| 主要坑 | 漏一个服务 = 新旧混用 401 | 两个 host 要一起改 | 服务端+客户端同窗口 + conf 属主 |
| 密码长度 | ≥64 字节 | ≥16 位 | ≥16 位 |

**通用前置**（每次轮换都做）：
```bash
cd /data/csmall
cp .env .env.bak.$(date +%Y%m%d)
cp docker-compose.yml docker-compose.yml.bak.$(date +%Y%m%d)
```

**密码生成**（一律 openssl rand，禁止 uuid/时间戳/自定义字符串）：
```bash
openssl rand -base64 48   # JWT（64 字符 = 64 字节，正好过 HS512 门槛）
openssl rand -base64 32   # MySQL / Redis（44 字符）
```

## 一、JWT_SECRET 轮换

### 步骤
```bash
# ① 生成新密钥
openssl rand -base64 48

# ② 改 .env（服务器 /data/csmall/.env）
#    JWT_SECRET=<新值>

# ③ 重建 11 个微服务（⚠️ restart 不生效，env 是容器创建时快照，必须 recreate）
cd /data/csmall && docker compose up -d
```

### 验证
```bash
# 11 容器 env 全部 = 新值且一致
for c in csmall-sso csmall-product csmall-order csmall-seckill csmall-ums csmall-ams csmall-front csmall-search csmall-ai csmall-resource csmall-gateway; do
  echo "$c: $(docker inspect $c --format '{{range .Config.Env}}{{println .}}{{end}}' | grep ^JWT_SECRET= | cut -c1-30)"
done
# 业务回归: 重新登录拿新 token → 访问需认证接口 200
# 反向: 拿旧 token → 401（证明旧密钥已失效）
```

### 注意事项
- 换密钥 = 所有已签发 JWT 立即失效 → **选低峰期，全员重新登录**
- 若发现某服务仍 401 → 单独 `docker compose up -d <服务>`（大概率是漏重建）
- 企业级平滑轮换（kid 版本化双密钥宽限期）见《TODO第一批实现与原理》§1.6，本项目暂用粗暴切换

## 二、MySQL root 密码轮换

### 步骤
```bash
# ① 生成新密码并改 .env 的 MYSQL_ROOT_PASSWORD

# ② 用【旧密码】连进去，一条连接改两个 host（⚠️ 关键坑！分开执行会因 localhost 已改导致 % 连不上）
docker exec csmall-mysql mysql -uroot -p'<旧密码>' -e "
  ALTER USER 'root'@'localhost' IDENTIFIED BY '<新密码>';
  ALTER USER 'root'@'%' IDENTIFIED BY '<新密码>';
  FLUSH PRIVILEGES;"

# ③ 重建 7 个连 DB 的服务（sso 三数据源 + product/order/seckill/ums/ams/resource）
cd /data/csmall && docker compose up -d mall-sso mall-product mall-order mall-seckill mall-ums mall-ams mall-resource
```

### 验证
```bash
docker exec csmall-mysql mysql -uroot -p'<新密码>' -e "SELECT 1;"   # 成功
docker exec csmall-mysql mysql -uroot -p'<旧密码>' -e "SELECT 1;"   # 应被拒 Access denied
# 微服务日志无 DB 连接错误
```

### 注意事项
- **为什么不能只改 .env**：compose 的 `MYSQL_ROOT_PASSWORD` 只在数据卷首次初始化时生效，数据已存在 → 必须 `ALTER USER`
- 两个 host 含义：`localhost` = 容器内 healthcheck 用；`%` = 微服务 TCP 连接用
- 密码含特殊字符（`/` `+` `=`）在 SQL 单引号内安全；shell 传递用单引号包裹

## 三、Redis 密码轮换

### 步骤（⚠️ 三处同步，服务端与客户端同一维护窗口，任一中间态 = 全站 Redis 挂）
```bash
# ① 生成新密码
openssl rand -base64 32

# ② 改 .env 的 REDIS_PASSWORD（服务器 + 本地 deploy/docker/.env 都要改）

# ③ 改 conf 两处: requirepass + masterauth
#    ⚠️ conf 属主是容器 redis 用户(999)，宿主机 ecs-user 直接 sed 可能权限不足，
#       用 docker root 方式改（无需 sudo）：
docker run --rm --user root -v /data/csmall/redis:/data/redis redis:7-alpine \
  sh -c "sed -i 's|^requirepass .*|requirepass <新密码>|; s|^masterauth .*|masterauth <新密码>|' /data/redis/redis-master.conf && chown redis:redis /data/redis/redis-master.conf && chmod 600 /data/redis/redis-master.conf"

# ④ 重建 redis + 11 个微服务（同窗口原子切换）
cd /data/csmall && docker compose up -d
```

### 验证
```bash
RP=<新密码>
docker exec csmall-redis redis-cli ping            # NOAUTH（无密码被拒）
docker exec csmall-redis redis-cli -a "$RP" ping   # PONG
# 微服务日志无 Redis 连接错误；秒杀/登录/token黑名单 回归
```

### 注意事项（三个坑，来自实战 §9.3/9.4）
1. **原子切换**：conf（服务端）与 11 服务 `SPRING_DATA_REDIS_PASSWORD`（客户端）必须同一窗口
2. **conf 属主**：必须是 redis 用户(999:1000)，不是 ecs-user；用 docker root chown
3. **三处一致**：`.env`、`redis-master.conf`、本地 `.env` 的 REDIS_PASSWORD 完全相同
4. 若同时涉及 AOF 首次开启/数据迁移，先热 `CONFIG SET appendonly yes`（教训见 §9.2）

## 五、执行纪律（红线）

1. **默认低峰期**：JWT 轮换会踢全体下线，MySQL/Redis 有短暂连接中断
2. **先备份**：.env + compose 各 cp 一份（含日期后缀）
3. **密码只进 .env / conf / 本地备忘录**：绝不写进 docs/、代码、聊天
4. **本地与服务器同步**：改完服务器 .env 立即同步本地 deploy/docker/.env
5. **验证再收工**：一致性检查 + 业务回归全过才算完成
6. **redis.conf 挂载不加 :ro**（Redis 会 REWRITE 自身 conf）

## 六、附：改服务器文本配置的标准姿势（不用 `vi`）

> **来源**：2026-09-12 从 [[项目上下文文档]] 附录 A.1 **迁入**（该处已留指针）—— 这是「改 `.env` / `nginx.conf` 等纯文本」的通用手法，与本文的 JWT / MySQL / Redis 轮换配套使用。

**🆘 `vi` 卡住的救命令**：按 `Esc`，然后 `:q!` + 回车（**不保存退出**）/ `:wq` + 回车（保存退出）。

### 6.1 快用版（日常改配置足够）

```bash
cd /data/csmall
cp -a .env .env.bak-$(date +%F_%H%M)                 # ① 先备份（带时间戳）
# ② 改「键=值」型配置：已存在就改，不存在就追加
grep -q '^RABBITMQ_USERNAME=' .env && sed -i 's|^RABBITMQ_USERNAME=.*|RABBITMQ_USERNAME=cs_mq_admin|' .env || echo 'RABBITMQ_USERNAME=cs_mq_admin' >> .env
read -rp '把新密码粘进来后回车: ' P
grep -q '^RABBITMQ_PASSWORD=' .env && sed -i "s|^RABBITMQ_PASSWORD=.*|RABBITMQ_PASSWORD=$P|" .env || echo "RABBITMQ_PASSWORD=$P" >> .env
unset P
# ③ 核对（密码只露前 4 位）
grep -E '^RABBITMQ_(USERNAME|PASSWORD)=' .env | sed -E 's/(PASSWORD=.{4}).*/\1***/'
```

> ℹ️ `sed` 用 `|` 当分隔符 ⇒ 密码里的 `/` `+` **不需要转义**（`openssl rand -base64 24` 只产出 `A-Za-z0-9+/`，**不含** `|` 与 `&`）✅

### 6.2 完整版（切凭据 / 换密码时用）

```bash
cd /data/csmall && cp -a .env .env.bak-$(date +%F_%H%M)      # ① 先备份

# ② 把要改的键改成静态值（本例：用户名）
grep -q '^RABBITMQ_USERNAME=' .env && sed -i 's|^RABBITMQ_USERNAME=.*|RABBITMQ_USERNAME=cs_mq_admin|' .env || echo 'RABBITMQ_USERNAME=cs_mq_admin' >> .env

# ③ 需要手输的值：用 read 读进变量（不要把密码写在命令行里 —— 会进 history/ps）
read -rp '把密码粘进来后回车: ' P          # 方式 A：可见（便于当场核对）
# read -rsp '把密码粘进来后回车（不显示）: ' P; echo   # 方式 B：静默（录屏/有人旁观时用）

# ④ 写进配置（存在则改、不存在则追加）
grep -q '^RABBITMQ_PASSWORD=' .env && sed -i "s|^RABBITMQ_PASSWORD=.*|RABBITMQ_PASSWORD=$P|" .env || echo "RABBITMQ_PASSWORD=$P" >> .env
unset P

# ⑤ 核对（**只回显前 4 位**，不要打印明文）
grep -E '^RABBITMQ_(USERNAME|PASSWORD)=' .env | sed -E 's/(PASSWORD=.{4}).*/\1***/'
```

**🔑 切凭据前的必做校验（2026-09-12 实战教训）**：改完 `.env` **先验"这组凭据在服务端能用"**，再去 recreate 服务 —— 否则会把服务改成**连不上中间件**：

```bash
# RabbitMQ 例：只用 .env 里的值去认证，不改任何状态、不打印密码
docker exec csmall-rabbitmq rabbitmqctl authenticate_user \
  "$(grep -E '^RABBITMQ_USERNAME=' /data/csmall/.env | head -1 | cut -d= -f2-)" \
  "$(grep -E '^RABBITMQ_PASSWORD=' /data/csmall/.env | head -1 | cut -d= -f2-)" | tail -2   # 期望 Success
```

> 🔴 **凭据卫生三铁律**：
> 1. **改前必备份**：`cp -a .env .env.bak-$(date +%F_%H%M)`（可一条命令回滚）。
> 2. **改后只回显前 4 位**；**任何明文密码都不要贴进聊天 / 文档 / 提交 / 工单**。
> 3. **明文一旦出现在聊天/文档/提交里 ⇒ 视为已泄露 ⇒ 立刻轮换**：
>    `docker exec csmall-rabbitmq rabbitmqctl change_password <user> '<新密码>'` → 同步各机 `.env`（用上面的标准姿势）→ `docker compose up -d <依赖服务>` → 再用 `authenticate_user` 复验。
